# Vexel 0.8 开发计划：界面简化、功能审核与稳定、AI（网关、Agent、训练与本地模型）

状态：**已确认**（2026-11-28）。签名主体待定，阶段 2 前需要决定（见第 5 节）。

## 0. 已确定的决定

| 问题 | 决定 |
| :-- | :-- |
| 产品界面 | **桌面版**（PySide6）是唯一的产品界面。Web 工作台冻结：保留代码，不加新功能，不在本计划内维护。 |
| 大模型密钥 | **由我们自己的 AI 网关持有**：软件里不再出现任何 API 密钥；网关负责额度、限流和“只做图像分析”的规则。 |
| GPU 租用 | **AutoDL（国内）与 Modal / RunPod（海外）两个后端，同一种训练任务格式**。 |
| 第一批模型 | **SEM 颗粒**（相互接触、叠加的颗粒）与**微流控液滴**（液滴与其中的细胞）。 |
| 范围 | 本计划的范围与阶段顺序已确认。**三维相关**（三维体分析的移植、SEM 倾转 2.5D 重建）与**大型图像数据分析**（多 GB 图像、OME-Zarr 金字塔、拼接大图）**放到下一阶段**：0.8 不做新开发，SEM 的“三维”页改为预览功能，默认隐藏。 |
| AI 网关 | 默认部署在**新加坡**。 |
| 数据 | **同意**：图片默认不发送给大模型；客户数据默认不上传训练，只有组织明确同意才可以。 |

## 1. 现状评估

### 1.1 界面（桌面版）

- **SEM 窗口**：工具栏一次显示 18 个按钮（11 种绘图工具、撤销/重做、适应窗口、导出、载入测量记录、诊断包、语言切换），右侧 5 个标签页（标定、图像处理、测量、自动测量、三维）始终都在。“自动测量”一页同时摆出规划、方法、区域、运行、纠错、按例子调整、方案、批量等 20 多个控件，大多数在还没有测量时是灰的。饱和区域用红色常驻叠加在图上，初次使用的人容易以为是测量结果。
- **液滴窗口**：三步布局是清楚的，但“在线监控”“批量分析”“自动规划”在没有数据时就占据第一屏；只有“帮助”一个菜单。
- **启动器**：SEM 模块仍标“开发中”。
- 已有可复用的基础：分步提示（`guide.py`）、诊断包（`bugreport.py`）、离线 GUI 测试（`tests/test_gui.py`）、可用性测试方案（`docs/usability_test.md`）。

### 1.2 功能与稳定性

- 计量算法有合成与真实图片的验收（线宽、孔、颗粒、纤维、层厚、侧壁、尖端、嵌套区域、导线与焊盘），完整测试套件通过。
- **只在 macOS（Apple Silicon）上完整测试过**；Windows、Intel Mac 没有测试，也没有安装包签名（签名主体未定）。
- `docs/closed_testing/known_issues.md` 停留在 0.6.0b1，没有反映 SEM 模块。
- 从 Web 移植到 Python 的剩余两项（叠加颗粒、三维体分析）是为 Web 工作台做的：三维体分析与其他三维功能放到下一阶段，叠加颗粒并入第一批模型（SEM 颗粒）。

### 1.3 大模型与 Agent

- 桌面版已有规划器：离线规则引擎（总是兜底）+ Claude、DeepSeek、通义千问、Gemini、本地模型等档位。输出经 JSON 结构和设置白名单（`check_settings`）校验；对液滴会**先在前几百帧上试跑**再给出方案。
- 问题：
  - 密钥放在用户电脑的环境变量里，**无法限制用量**，也挡不住用户拿同一个密钥去做别的事。
  - 桌面版的 OpenAI 兼容档位（DeepSeek、通义千问、Gemini）**没有设置输出 token 上限**，只有 Claude 档位限制在 4,000；Web 工作台的 Gemini 与 OpenAI 兼容接口同样没有上限，用量按每次固定估价记录，不是实际消耗。
  - 云端模型的规划**准确率从未系统测量**。
  - 第一个 SEM 用户是半导体企业：**图片默认不能离开本机**，规划只能基于图像统计特征（指纹），除非该企业明确允许。

### 1.4 训练与本地模型

- 桌面版：画笔训练（随机森林，两类）；ONNX 推理运行时（硬件选择、分块拼接、SHA-256 校验）和模型卡（`ModelCard`）已经有了，**但没有接到任何测量流程上**，也没有“导入模型”的界面。
- `web/deploy/gpu-worker`：LoRA 训练容器与 Modal、RunPod 模板，**从未在 GPU 上跑过**，编码器没有预训练权重。
- Intel Mac 没有 onnxruntime 安装包：那里不能用模型。

## 2. 需求细化

### 2.1 界面：尽量简单，按步骤出现

1. **一步只突出一个主要操作**，按“打开 → 标定 → 测量 → 结果/导出”的顺序推进；当前步骤没用到的控件隐藏，而不是变灰。
2. **按需出现**：
   - 有测量结果后才出现“纠错”“按例子调整”“存为方案”；
   - 有两张以上图片或已存方案后才出现“批量”；
   - 用户打开时才出现“图像处理”和“三维”。
3. **工具栏精简到约 7 个常用项**（打开、选择、长度、面积、计数、撤销、导出），其余绘图工具收进“更多工具”；语言、诊断包、载入记录移到菜单。
4. **提示代替说明书**：每一步在固定位置给一句“下一步做什么”；警告（饱和、未标定、模型不可用）以醒目的标记出现，点开才看详情。
5. 默认值就是推荐值：高级设置收起，并注明“一般不用改”。
6. **度量**：SEM 窗口首屏可见控件减少一半以上；可用性测试中新用户不看手册完成“打开 → 标定 → 自动测量 → 导出”的成功率 ≥ 80%。

### 2.2 功能最终审核与稳定

1. **功能清单逐项定级**：保留并验收 / 隐藏为预览（`VEXEL_PREVIEW`）/ 删除。每个保留的功能要有证据（基准、真实图片或测试），没有证据的不进正式版。
2. **不崩溃**：任何文件、任何操作都不能让程序退出；后台任务出错一律变成可理解的提示，并可一键生成诊断包。
3. **平台**：Windows 10/11、macOS（Apple Silicon 和 Intel）都要通过同一套测试；CI 加入 Windows 与 macOS。
4. **稳定期冻结新功能**：只修错和简化。

### 2.3 大模型与 Agent：受控、可度量

1. **只有结构化请求**：
   - 软件只发“规划工作流”一类请求，内容是图像指纹、可选的一句目标（≤ 200 字）和允许的方案目录（由网关保存，不由客户端提供）；
   - 回答必须符合 JSON 结构，经白名单校验后才生效；
   - **没有聊天窗口**，模型的文字只作为方案理由显示，有长度上限。
2. **拒绝其他用途**：
   - 网关先用规则过滤与图像分析无关的请求和提示词注入（不消耗 token）；
   - 模型的回答带“超出范围”标志，带此标志的回答直接拒绝；
   - 网关不提供任何通用对话接口。
3. **token 上限**（初值，可调）：

   | 项目 | 上限 |
   | :-- | :-- |
   | 每次输入 | ≤ 3,000 tokens |
   | 每次输出 | ≤ 600 tokens |
   | 每个规划的修正轮数 | ≤ 3 轮 |
   | 每个用户每天 | ≤ 30 次规划，或 50k tokens |
   | 每个组织每月 | 预算上限，超出后自动降级为离线规则引擎 |

   - 用量按服务商返回的**实际 token 数**记账。
   - 相同图像指纹与目标的请求直接返回缓存，不再调用模型。
4. **图片**：默认不发送。组织策略允许时，才发送缩小到 768 像素以内的 JPEG。日志不保存图片。
5. **服务商路由**：中国大陆用户默认 DeepSeek，海外用户默认 Gemini，任一不可用时降级到另一个或离线规则。
6. **Agent 建立建议工作流**：
   - 流程：选测量方法与设置 → **在本机对当前图片试跑** → 按质控结果修正（≤ 3 轮）→ 给出方案、试跑结果与理由。
   - 用户接受后保存为“方案”，可用于批量。
   - Agent 只能使用软件已有的、经过验收的测量与处理步骤，不能写代码，也不能调用外部工具。
7. **精准度要有数**：用标注好的评测集（见第 4 节）比较各服务商与离线规则；某个服务商只有在评测集上不低于离线规则时才启用。

### 2.4 训练与本地模型

1. **原则：AI 负责分割，计量仍由经过验收的确定性算法完成。** 模型给出颗粒或液滴的区域，尺寸仍按灰度边缘测量，所以计量精度不依赖模型。
2. **数据**：
   - 合成数据：接触、叠加的颗粒，带细胞的液滴，精确真值；
   - 我们自己的真实数据，在软件里用画笔、纠错标注后导出成训练包；
   - **客户数据默认不上传云端**：只有组织明确同意才可以，否则用客户自己的 GPU，以及同一个容器的本地模式。
3. **训练任务**：一种声明式任务格式，包括数据包、模型类型、参数白名单、时长与费用上限。网关负责提交到 AutoDL 或 Modal/RunPod，结果回传。
4. **输出**：
   - ONNX 模型；
   - 模型卡：任务、输入要求（通道、像素尺寸、归一化）、训练数据说明、许可证；
   - SHA-256；
   - 留出集上的指标，以及一小组随模型附带的验收图片。
5. **本地导入**：
   - “导入模型”对话框：校验模型卡与 SHA，在附带的验收图片上试跑，结果和指标一致才注册；
   - 颗粒测量与液滴识别多出一个选项，“模型（名称、版本）”。
6. **预训练权重**：只用许可证允许商用的权重，并记录在模型卡里。

## 3. 开发计划与阶段性验证

每个阶段结束都有**验证门**：门内各项全部满足，才进入下一阶段。表中的工期是粗略估计。

### 阶段 0　准备与功能审核（约 1 周）

- 功能清单：桌面版所有功能逐项定级（保留 / 预览 / 删除），写出每项的验收证据。
- 冻结 Web 工作台；三维相关与大型图像数据分析移到下一阶段，SEM“三维”页改为预览功能。
- 更新 `known_issues.md`。
- 准备 Windows 与 Intel Mac 测试机，在 CI 中加入 Windows 与 macOS。
- 建立两个评测集的框架：规划评测集、分割评测集。

**验证门 0**：功能清单经你确认；CI 在三种平台上运行现有测试，失败项列成清单。

### 阶段 1　界面简化（约 2–3 周）

- 先出界面方案（每一步的截图稿）。**方案确认后才改代码。**
- 改造 SEM 窗口：
  - 步骤式右栏；
  - 精简工具栏，其余工具收进“更多工具”；
  - 结果相关的控件在有结果后才出现；
  - 警告改为标记。
- 改造液滴窗口：在线监控、批量、自动规划移入菜单，或在合适的步骤出现。
- 启动器去掉 SEM 的“开发中”（阶段 2 通过后）。
- 更新 GUI 测试；所有界面状态做截图回归。

**验证门 1**：

- SEM 首屏可见控件减少 ≥ 50%；
- GUI 测试全部通过；
- 3–5 位测试者做可用性测试（按 `usability_test.md`），新用户完成核心流程的成功率 ≥ 80%，记录用时与出错点。

### 阶段 2　稳定性（约 2–3 周，可与阶段 1 后半段并行）

- 错误路径审查：所有后台任务、文件读取、导出的异常都转为提示，不让程序退出。
- 鲁棒性样本库（约 100 个文件）：超大图、16 位、RGB、多页 TIFF、损坏文件、空白图、极端标定、长视频；自动跑完整流程。
- 性能预算：
  - 打开 8k SEM 图 < 3 秒；
  - 自动测量 < 10 秒；
  - 内存 < 4 GB。
- 三平台测试与安装包。安装包签名需要你先定签名主体。

**验证门 2**：

- 样本库 0 次崩溃；
- 三平台测试全部通过；
- 性能达标；
- 发 0.8.0b1 测试版，两周内测试者报告的崩溃为 0。

### 阶段 3　AI 网关与 Agent（约 3–4 周）

- 网关服务（Python FastAPI，部署在新加坡，中国大陆与海外都能访问）：
  - 账号与组织；
  - 服务商路由：DeepSeek 与 Gemini；
  - 结构化接口与规则过滤；
  - token 上限、实际用量记账与预算；
  - 缓存；
  - 不存图片的审计日志。
- 桌面端：
  - 规划档位改为“Vexel 网关”，删除用户自填密钥的选项；
  - 组织策略控制是否允许发送图片。
- Agent：SEM 与液滴两个模块都支持“规划 → 本机试跑 → 修正 → 给出方案 → 保存为方案”。
- 评测集：
  - 规划评测集约 60 张，SEM 与液滴各半，标注正确的方法与关键设置；
  - 红队集约 150 条，包括无关请求、提示词注入、越权要求。

**验证门 3**：

- 红队集 100% 拒绝；
- 每个规划的 token 用量 p95 不超过上限；
- 启用的服务商在规划评测集上的准确率不低于离线规则，并给出各服务商的分数表；
- 断网或额度用完时自动降级为离线规则，功能不中断。

### 阶段 4　训练流水线（约 4–6 周）

- 数据：
  - 合成生成器：接触与叠加的颗粒、带细胞的液滴，都带实例级真值；
  - 软件内标注导出成训练包；
  - 数据同意记录。
- 训练容器：
  - 一个镜像，两个后端（AutoDL、Modal/RunPod）；
  - 预训练权重，许可证需核对；
  - 实例分割模型，例如 U-Net 加距离图或中心点头，具体在阶段内比较后选定；
  - 导出 ONNX 与模型卡；
  - 每个任务有时长与费用上限。

**验证门 4**：

- 同一任务在两个后端上训练，留出集指标差异 < 2%；
- 结果可复现，固定随机种子；
- 每个模型都有完整的模型卡与验收图片；
- 单次训练费用在设定上限内。

### 阶段 5　本地导入与集成（约 2–3 周）

- “导入模型”对话框：校验、试跑、注册与删除。
- 颗粒测量与液滴识别加入模型选项：模型分割，确定性算法计量。
- 在 Windows 与 macOS 的 CPU 上测推理速度。

**验证门 5**：

- 接触、叠加的颗粒：模型路线的计数与尺寸明显优于阈值路线（具体目标在阶段 4 末，根据基线确定）；
- 简单图像：两条路线结果一致，差异在现有验收误差内；
- 液滴：现有液滴基准不退步，细胞计数准确率提高；
- 4k 图 CPU 推理 < 10 秒；
- Intel Mac 上明确提示“不支持模型”，不出错。

### 阶段 6　最终审核与发布（约 1–2 周）

- 全部验证门复核；用户手册、已知问题、测试者说明更新。
- 发 0.8.0 测试版，收集反馈。

**验证门 6**：你确认发布。

**总工期**约 15–22 周。阶段 1 与 2 部分并行；阶段 3 与 4 可以由不同的人并行。

## 4. 风险

| 风险 | 应对 |
| :-- | :-- |
| 客户图片外传（半导体企业） | 图片默认不发；训练默认不上传客户数据；组织策略显式开启。 |
| 大陆访问 Gemini 不通，海外访问 AutoDL 慢 | 按地区路由，任一不可用时降级。 |
| 云端模型准确率不如规则 | 用评测集把关，不达标的服务商不启用。 |
| 训练数据不够 | 先用合成数据加自有数据；客户微调放在客户本地。 |
| 安装包签名主体未定 | 阶段 2 前需要决定，否则 Windows 安装会被系统拦截提示。 |
| 网关运维与费用 | 每月预算上限与告警；网关不可用时软件仍可离线使用。 |

## 5. 安装包签名：建议

**原则**：用将来对外销售、与客户签合同的那家公司签名，不用个人账号。企业客户（例如半导体厂）的 IT 部门会核对安装包上的发布者名称，它应当与合同主体一致。

| 平台 | 建议 | 需要准备 |
| :-- | :-- | :-- |
| macOS | Apple Developer Program 的**组织会员**（每年 99 美元），用“Developer ID Application”证书签名，再经 Apple 公证（notarization）。 | 公司的 D-U-N-S 编号（多数地区免费，约 5 个工作日；中国大陆公司可通过邓白氏申请）、公司官网与该域名的工作邮箱、有权签署协议的人。 |
| Windows，公司注册在美国、加拿大、欧盟或英国，且有 3 年以上可核实的经营历史 | 微软 **Azure Artifact Signing**（原 Trusted Signing）：云端签名，按月付费，适合在 CI 里自动签名。 | 付费 Azure 订阅、公司身份验证。 |
| Windows，公司注册在中国大陆或其他地区 | 向 DigiCert、Sectigo 或 GlobalSign 购买**组织验证（OV）代码签名证书**，选**云签名**而不是 USB 令牌，以便 CI 自动签名。 | 营业执照等公司验证材料；云签名服务的账号。 |

补充说明：

- **不必买更贵的 EV 证书**。微软已不再给 EV 证书自动的 SmartScreen 信誉，OV 与 EV 都要靠下载量逐步积累信誉。新证书签的安装包，在头几周仍可能出现“未知发布者”的提示，测试者说明里要写清楚“仍要运行”的操作。
- 每个文件都加**时间戳**，证书过期后签名依然有效。
- 签名密钥只放在签名服务里，不进代码仓库，也不放在个人电脑上。
- 时间上，Apple 的组织验证与证书申请通常要 1–3 周，应在阶段 2 开始前启动。

**需要你提供**：用哪家公司签名，以及它注册在哪里。注册地决定 Windows 走 Azure Artifact Signing 还是 OV 证书。
