# 第三阶段（流式执行）验收记录

日期：2026-11-14。复现：`uv run python tests/benchmarks/stream_acceptance.py --out docs/phase3_acceptance_table.md`（真实录像不在仓库中，见用户手册第 9 节；找不到时只跑合成视频）。

## 验收标准（路线图第十节）

> 回放真实视频时在线指标与录后全量分析一致；给出软件处理帧率与丢帧率。

## 方法

每段数据先做一次批式全量分析（`vexel run` 的引擎），再按不同送帧速率回放（`vexel replay` 的引擎），比较：

- 在线计到的液滴数与全量分析在同一帧范围内的液滴数；
- 每个液滴的细胞数（两者液滴数相同时逐个比较）；
- 处理速度、丢帧比例（抽样跳过 + 队列满丢弃）、延迟中位数（帧到达到处理完，只在按帧率回放时记录）；
- 是否报出“处理能力”警报（队列满丢帧，或隔帧过多以致每个液滴穿过视野时只被看到不足 3 次）。

“不限速”行测的是软件本身的最大处理速度；其余各行按给定帧率送帧，跟不上时自动隔帧处理（每 2、4、8、16 帧处理 1 帧）。

## 结论

1. **跟得上时完全一致。** 送帧速率不超过处理能力时，三段数据的在线液滴数都与全量分析相同，细胞数 99%–100% 相同（WSCNet 序列上差 1 个液滴，来自在线估计的背景与全量的略有不同）。
2. **处理能力。** 本机上不限速处理：512×104 明场约 90 帧/秒；290×116 加细胞计数约 60 帧/秒；768×256 加细胞计数约 38 帧/秒。
3. **超负荷时按比例抽样，计数仍可靠。** 合成视频送帧为处理能力的 2 倍（80 帧/秒，跳过 60% 的帧）时，液滴数与细胞数仍与全量分析完全一致。
4. **抽样的极限会被报出来。** 隔帧过多时（WSCNet 序列送帧 100 帧/秒，液滴排得很密、帧间位移又不均匀；合成视频送帧 160 帧/秒），在线计数不全，这两种情况都报出了“处理能力”警报；所有计数完整的情况都没有误报。在线结果旁边有这条警报时，应以采集后的全量分析为准（`vexel watch` 默认会在采集结束后自动做一次）。

## 局限

- 两段真实录像都很短（101 帧、300 帧），只能检验一致性，看不出长时间稳定运行时的丢帧率；稳定状态下的丢帧数据来自 2000 帧的合成视频。**路线图要求的“客户真实视频”验收仍需客户提供长录像。**
- 计时只含软件处理，不含相机读出与传输，不是端到端延迟；开头建立背景时缓存的 64 帧不计入延迟。
- WSCNet 序列的真实帧间隔未知，按名义 10 ms 回放；.mov 按其标注的 7 帧/秒回放（很可能是慢放片段）。
- 只在一台机器（Apple M5 Pro）上测过。
