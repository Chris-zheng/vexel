# Vexel 用户手册

适用版本：0.7.0b2 内测版。微流控液滴模块为内测版（Phase 1–6 完成）；SEM 扫描电镜模块为**预览版**（读取与标定、手动测量、图像处理、半导体计量与分割、材料测量、识别与自动规划、倾转 2.5D 已完成；标定与颗粒测量已在真实图片上验收两轮，半导体计量待第一位用户的真实图片验收）。

Vexel 是一个科学图像分析平台，由彼此独立的**模块**组成：

- **微流控液滴**：分析微流控液滴的 2D 明场（及荧光）时序图像，即录好的视频或图像序列；
- **SEM 扫描电镜**：分析扫描电镜图片，重点是半导体尺寸计量。

每个模块都有桌面界面和命令行两种用法，两者调用同一套分析方法，默认设置下结果相同。

## 1. 安装

需要 [uv](https://docs.astral.sh/uv/)（会自动准备 Python 3.12）。还没有 uv 时：

- macOS / Linux：`curl -LsSf https://astral.sh/uv/install.sh | sh`
- Windows（PowerShell）：`powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`

装完重新打开终端。然后二选一：

**从安装文件**（内测时收到的 `.whl`，连同 `vexel-0.7.0b2-constraints.txt`）：

```bash
uv tool install ./vexel-0.7.0b2-py3-none-any.whl -c ./vexel-0.7.0b2-constraints.txt
vexel gui
```

`-c` 让依赖装成我们测试过的确切版本。在中国大陆网络下，先按 [内测说明](closed_testing/README.md) 1B 节设置国内镜像。

这样装好后命令直接写 `vexel ...`；卸载用 `uv tool uninstall vexel`。要用 SEM 模块的文字识别（读取信息栏上的比例尺），把文件名写成 `"./vexel-0.7.0b2-py3-none-any.whl[agent,sem]"`（带引号）。

**从源码**：

```bash
git clone https://github.com/Chris-zheng/vexel.git
cd vexel
uv sync                  # 要用 Claude 规划或 MCP 服务时：uv sync --extra agent；SEM 文字识别：--extra sem
```

确认安装成功：

```bash
uv run vexel --help
```

桌面界面随同安装，不需要额外步骤。DeepSeek、通义千问、Gemini、本地模型不需要额外安装（见 5.7 节）。

下文所有命令都写成 `uv run vexel ...`（源码方式）。如果已激活虚拟环境（`source .venv/bin/activate`），或用安装文件装的，直接写 `vexel ...`。装好后怎样打开软件见第 2 节。

最低系统：Windows 10/11 x64、macOS 14、glibc 2.34 及以上的 Linux（如 Ubuntu 22.04、RHEL 9），由 Qt 界面库 PySide6 6.12 决定。

**无法联网的计算机**（如工厂内网）：使用离线安装包 `vexel-<版本>-offline-<平台>.zip`。它包含 uv、Python 和全部依赖。解压后在其中运行 `install.ps1`（Windows：`powershell -ExecutionPolicy Bypass -File .\install.ps1`）或 `sh install.sh`（macOS、Linux），全程不访问网络。离线包由 `uv run python scripts/build_offline_bundle.py --platform <windows-x64|macos-arm64|macos-x64|linux-x64>` 在可联网的机器上生成。

测试平台：macOS（Apple Silicon）上完整测试并日常使用；Windows、Linux 已配置持续集成（CI，`.github/workflows/ci.yml`），每次提交运行全部测试并按测试者的方式安装试运行；尚未在真实的 Windows、Linux 桌面上人工使用过。

## 2. 启动 Vexel

### 2.1 打开桌面界面

在终端（Windows 的 PowerShell，macOS 的“终端”）里运行：

| 安装方式 | 命令 |
| :--- | :--- |
| 安装文件或离线安装包（`uv tool install`） | `vexel gui` |
| 源码（`uv sync`），在源码文件夹里运行 | `uv run vexel gui` |

也可以运行 `vexel-gui`：它和 `vexel gui` 相同，但在 Windows 上不会多开一个命令行窗口，适合做成桌面快捷方式（快捷方式的目标填 `vexel-gui` 的完整路径，用 `where vexel-gui`（Windows）或 `which vexel-gui`（macOS、Linux）查看）。

启动时可以直接给一个文件，Vexel 按文件判断属于哪个模块并直接打开它：

```bash
vexel gui data/demo/droplets.ome.tif     # 录像：进入液滴模块
vexel gui image.tif                      # SEM 图片：进入 SEM 模块（预览版需先打开，见 2.3）
```

第一次使用、手边没有数据时：液滴模块里点 **帮助 → 打开示例数据**，或先运行 `vexel synth data/demo` 生成一段合成视频。

### 2.2 选择模块

不带文件启动时，先出现**模块选择窗口**：每个模块一张卡片，点“打开”进入。

- 勾选“下次启动时直接打开上次使用的模块”，以后跳过选择窗口。
- 每个模块窗口都有 **模块** 菜单：可以同时打开另一个模块，或回到选择窗口。各模块窗口互不影响。
- 直接打开某个模块：`vexel gui --module droplet` 或 `vexel gui --module sem`。
- 查看有哪些模块、一个文件属于哪个模块：

```bash
vexel modules                  # 列出模块及状态
vexel modules my_file.tif      # 各模块对这个文件的判断（0–1 打分）
```

### 2.3 打开 SEM 模块（预览版）

SEM 模块还在开发中，选择窗口里显示为“开发中”，按钮不可用。要使用预览版，用 `--preview` 启动，或启动前设置环境变量 `VEXEL_PREVIEW=1`：

| 系统 | 命令 |
| :--- | :--- |
| 所有系统 | `vexel gui --preview`（只打开 SEM：`vexel gui --module sem --preview`） |
| macOS、Linux | `VEXEL_PREVIEW=1 vexel gui` |
| Windows PowerShell | `$env:VEXEL_PREVIEW=1; vexel gui` |
| Windows 命令提示符（cmd） | `set VEXEL_PREVIEW=1 && vexel gui` |

这样设置只对这一次启动有效。长期使用时可以把它加入系统的环境变量（Windows：设置 → 系统 → 关于 → 高级系统设置 → 环境变量；macOS：写入 `~/.zshrc`）。没有设置时，用 `--module sem` 或打开 SEM 图片都会回到选择窗口并说明原因。

SEM 的命令行（`vexel sem ...`）不受这个设置限制，随时可用。

SEM 的文字识别（读取信息栏上的比例尺数字）需要可选组件：离线安装包已包含；用安装文件安装时写成 `uv tool install "./vexel-<版本>-py3-none-any.whl[agent,sem]" -c ./vexel-<版本>-constraints.txt`；源码方式用 `uv sync --extra sem`。没有它时，标定仍可用仪器元数据或手动完成。

### 2.4 命令行

```bash
vexel --help                 # 全部命令
vexel <命令> --help          # 某个命令的用法，例如 vexel run --help、vexel sem tilt3d --help
```

| 命令 | 用途 | 见 |
| :--- | :--- | :--- |
| `info`、`probe`、`plan` | 看数据的元数据、指纹，自动规划配方 | 5.2、5.7 |
| `run`、`replay`、`watch` | 运行配方、在线回放、监视采集文件夹 | 5.4–5.6 |
| `batch` | 批量分析与分组统计 | 5.8 |
| `recipes`、`ops`、`validate`、`synth` | 配方、算子、用真值验证、生成合成数据 | 7–10 |
| `sem ...` | SEM：`info`、`calibrate`、`measure`、`profile`、`process`、`average`、`analyze`、`plan`、`tilt3d`、`report` | 11.10 |
| `report`、`convert`、`bugreport`、`policy`、`licenses`、`modules`、`plugins`、`mcp` | 其他 | 12 |

下文的命令都写成 `uv run vexel ...`（源码方式）；用安装文件装的，去掉 `uv run`，直接写 `vexel ...`。

### 2.5 数据和设置保存在哪里

| 内容 | 位置 |
| :--- | :--- |
| 液滴分析结果 | 你选择的输出文件夹（每次运行一个文件夹） |
| SEM 的标定确认、测量记录（含图像处理、自动测量、三维的设置） | `~/.vexel/sem/`（按图像文件的 SHA-256 存放，同一文件再次打开时恢复） |
| 配方记忆（自动规划参考的历史） | `~/.vexel/memory/` |
| 规划模型、界面语言等设置 | `~/.vexel/config.json` |
| 窗口位置、模块选择等界面偏好 | 系统的应用设置 |

`~` 是用户主目录（Windows 为 `C:\Users\<用户名>`）。环境变量 `VEXEL_HOME` 可以把 `~/.vexel` 换到别处，例如共享盘或便于备份的位置。除了你设置的规划模型，Vexel 不发出任何网络请求（见第 12 节“组织策略”）。

### 2.6 界面语言

液滴模块的界面是中文。SEM 窗口可以切换为英文：菜单 **帮助 → English**（英文界面下为 **Help → 中文**），下次打开 SEM 窗口时生效；或启动前设置 `VEXEL_LANG=en`。见 11.9。

## 3. 液滴模块：桌面界面

不习惯命令行时，用桌面界面完成全部常规分析。

打开方法、模块选择见第 2 节。本章以下内容都指液滴模块。

也可以启动时直接打开数据：`uv run vexel gui data/demo/droplets.ome.tif`。没有数据时，先用 `uv run vexel synth data/demo` 生成一段合成视频来熟悉界面。

窗口分左右两栏：左侧按 1、2、3 三步操作，右侧显示结果。打开窗口时左侧只有第 1 步（选择数据）；载入数据后才出现“想测什么”与自动规划、第 2 步的设置和第 3 步的分析按钮。右侧顶部的蓝色 **引导栏** 随时告诉你下一步做什么，并给出对应的按钮：没有数据时可以点 **试用示例数据**（生成一段带细胞的合成视频）；载入后先 **快速预览**；预览后判断红线是否套准，再 **开始分析** 或改用 **画笔训练**；分析完有可疑液滴时引导去 **复核与纠错**。熟悉之后点引导栏右边的 × 关掉，需要时从菜单 **帮助 → 显示引导** 打开。

**文件** 菜单：选择文件、图像序列文件夹，以及 **在线监控** 与 **批量分析**（3.8、3.10）。**帮助** 菜单里还有：**打开示例数据**；**规划模型设置…**（仅在 `VEXEL_PREVIEW=1` 时出现，见 5.7 节）；**导出诊断包…**（报告问题时附上，不含图像和密钥，见第 12 节）。

### 3.1 第一步：数据

点 **选择文件…** 选视频或 TIFF；图像序列和 OME-Zarr 用 **图像序列文件夹…**。也可以把文件直接拖进窗口。

载入后，文件名下方显示帧数、画面尺寸、数据类型和通道数。只读元数据，大文件也立即显示。多通道数据在第二步里选择各项分析用哪个通道。

### 3.2 第二步：设置

| 项 | 说明 |
| :--- | :--- |
| 像素尺寸 (µm) | 每个像素对应的实际长度 |
| 帧间隔 (ms) | 相邻两帧的采集时间间隔 |
| 流动方向 | 液滴在画面中左右流动选“水平”，上下流动选“竖直” |
| 流道高度 (µm) | 可不填。填写后，直径大于流道高度的液滴按被压扁的形状换算体积；不填则全部按球形换算（见 6.1 节） |
| 液滴通道 | 仅多通道数据。在哪个通道里分割液滴，选液滴轮廓最清楚的通道（通常是明场） |
| 包裹计数 | 勾选后统计每个液滴里的细胞数，给出空滴、单包裹、多包裹比例并与泊松分布比较（见 6.5 节） |
| 细胞所在通道 | 仅多通道数据且勾选包裹计数。在哪个通道里数细胞，例如细胞经荧光染色时选荧光通道 |
| 细胞外观 | 勾选包裹计数后出现。明场下细胞通常比液滴内部暗；荧光通道下细胞比液滴内部亮 |
| 荧光 | 勾选后测每个液滴的荧光强度，判为阳性或阴性，给出阳性比例和每滴平均拷贝数（见 6.6 节） |
| 荧光通道 | 仅多通道数据且勾选荧光。测荧光强度用的通道 |

界面里的通道从 1 开始编号；配方和命令行里的通道号从 0 开始，界面的“通道 2”即配方里的 `1`。通道名称（如 brightfield、fluorescence）取自文件元数据，没有时只显示编号。

文件里有标定信息时会自动填入，并提示“已从文件读取标定，请核对”。

**界面上显示什么就用什么。** 字段留空表示不标定，即使文件里有标定信息也不使用：像素尺寸留空时粒径以像素为单位，帧间隔留空时频率以“次/帧”为单位。

**打开视频时务必核对帧间隔。** 视频里记录的通常是回放帧率而不是相机采集帧率，界面会对此给出提示。

### 3.3 高级设置

点 **高级设置** 展开。默认值与所选内置配方一致（见 3.6 节）；鼠标悬停在每一项上有说明。改坏了点 **恢复默认**。

| 项 | 对应配方参数 | 什么时候调 |
| :--- | :--- | :--- |
| 最小 / 最大液滴直径 | `seg.min_diameter_px` / `seg.max_diameter_px` | 默认“自动”，按每帧液滴的典型大小确定查找范围。小卫星液滴被当成液滴时调高最小值；大小差别很大的液滴混在一起时手动给出范围 |
| 轮廓完整度 | `seg.min_score` | 圆周上至少有这一比例落在边缘上才算液滴（默认 0.35）。漏检时调低；凭空多出圆时调高 |
| 最低对比度 | `seg.motion_threshold` | 扣除背景后低于该灰度差的地方不找液滴边缘（会按噪声自动抬高）。漏检时调低；空白处误检时调高 |
| 最大帧间位移 | `track.max_distance_px` | 同一液滴被数成多个时调高；不同液滴被连成一条轨迹时调低 |
| 计数线位置 | `droplets.count_line` | 计数线处有遮挡或流道结构时移开 |
| 细胞直径 | `inclusions.cell_diameter_px` | 仅包裹计数。按实际细胞在图像中的像素直径填写；两个相邻细胞被数成一个时调小 |
| 细胞最低对比度 | `inclusions.min_contrast` | 仅包裹计数。默认“自动”，按每帧估计的噪声设阈值；漏数细胞时填一个较小的值，空液滴被数出细胞时填一个较大的值 |
| 阳性阈值 | `positivity.threshold` | 仅荧光。默认“自动”；填入数值即改为固定阈值（等同于 `positivity.method=fixed`）。自动判读提示只发现一群液滴、或两群重叠时，用阴性和阳性对照确定阈值后填在这里 |

各项的详细含义与调整思路见第 8 节。

### 3.4 第三步：分析

- **快速预览**：只分析前 200 帧，几秒内出结果，用来检查设置是否合适。预览结果放在临时目录，关闭程序后删除，不计算输入文件指纹。
- **开始分析**：分析全部帧。结果保存在数据所在文件夹下的 `<文件名>_vexel/<日期-时间>/`；该文件夹不可写时保存到 `~/Vexel/<文件名>_vexel/<日期-时间>/`。

运行中左下角显示进度和当前步骤，可以随时 **取消**；取消后不留下不完整的结果。

建议流程：先快速预览，看复核图里的轮廓是否贴合；不合适就调高级设置再预览；满意后再开始分析。

### 3.5 结果

右侧从上到下：

- **四个关键数字**：液滴数、平均粒径、粒径 CV、生成频率，每项下方附补充（轨迹数、标准差与平均体积、粒径范围、平均间距）。各项含义见 6.1 节。
- **包裹统计**（勾选包裹计数时）：平均每滴细胞数 λ 及其 95% 置信区间与细胞浓度（个/µL）；空滴、单包裹、多包裹的实测比例，下方附泊松预期。各项含义见 6.5 节。
- **荧光判读**（勾选荧光时）：阳性液滴比例（附阳性数 / 总数与 95% 置信区间）；每滴平均拷贝数及其区间；浓度（拷贝/µL）及其区间；阴阳分离度 D、阈值及其确定方式。各项含义见 6.6 节。
- **黄色提示条**（只在需要时出现）：预览结果、未标定、没有检测到液滴、质控规则提示等。出现时应先看复核图确认结果。
- **复核图**：均匀抽取的 4 帧，红线为液滴轮廓；包裹计数时黄圈为检出的细胞。勾选荧光时，底图为荧光通道。用 **上一张 / 下一张** 翻看；点图片用系统看图软件打开原图。检查要点见 6.3 节。
- **可疑液滴**（有时才出现）：需要人工确认的液滴的缩略图，下方写明原因（形状不圆、粒径异常、计数不稳、近阈值、帧数少）。点缩略图在上方大图中查看并显示完整原因；点 **上一张 / 下一张** 回到复核图。见 6.7 节。
- **粒径分布**：每个液滴一个计数，虚线为均值。
- **包裹数分布**（勾选包裹计数时）：每滴含 0、1、2… 个细胞的液滴比例，蓝色为实测，灰色为泊松预期。
- **粒径与荧光**（勾选荧光时）：每个液滴一个点，蓝色为阳性、灰色为阴性，虚线为阈值。阴阳两群应上下分开；阈值附近点多时，判读结果需谨慎对待。

右上角 **打开报告** 用浏览器打开单文件 HTML 报告（见 6.8 节），可直接发送或打印；**打开结果文件夹** 打开保存目录，里面的表格、溯源记录与命令行运行的完全相同（见第 6 节）。

要查看以前的结果：在尚未载入数据时，点右侧的 **打开已有结果…**，选择一次运行的结果文件夹。

### 3.6 界面与命令行的对应关系

默认设置下，界面运行与下面的命令使用同一个配方，`provenance.json` 中的配方哈希相同：

```bash
uv run vexel run <数据> -r droplet_basic --pixel-size <像素尺寸> --frame-interval <帧间隔(秒)>
```

界面按勾选的分析内容选用内置配方：

| 包裹计数 | 荧光 | 配方 |
| :--- | :--- | :--- |
| 否 | 否 | `droplet_basic` |
| 是 | 否 | `droplet_encapsulation` |
| 否 | 是 | `droplet_fluorescence` |
| 是 | 是 | `droplet_fluorescence_encapsulation` |

其他设置对应的命令行参数：细胞外观选“比液滴内部亮”为 `--set inclusions.polarity=bright`；流道高度为 `--set droplets.channel_height_um=<µm>`；液滴通道、细胞所在通道、荧光通道分别为 `--set input.channel=N`、`--set input.channels.cells=N`、`--set input.channels.fluo=N`（N 从 0 起）。

在高级设置里改过的参数，等同于命令行的 `--set`。实际使用的全部参数都记录在结果文件夹的 `recipe.json` 中。

### 3.7 画笔训练（液滴轮廓找不准时）

默认的“自动（找圆）”适用于圆形液滴。快速预览后发现红线没有套准（漏掉液滴、圈到杂质、轮廓明显偏大或偏小），把 **液滴识别** 改为 **画笔训练**，或点旁边的 **训练…**，打开画笔窗口：

- **液滴画笔**（蓝）：在液滴上画几笔，最好横穿整个液滴、包括它的深色边。
- **背景画笔**（橙）：在背景、流道壁、流道边缘、液滴之间的空隙和液滴外沿画几笔。
- **橡皮**：擦掉画错的笔画。**笔刷** 调粗细。
- 每画一笔，当前帧立刻显示识别效果：蓝色越深表示越像液滴，红线是由此得到的轮廓。哪里错了就在哪里补一笔：圈到了不该圈的，就在那里画背景；轮廓画大了，就沿液滴外沿画一圈背景。拖动下方滑块换一帧检查，也可以在那一帧上画。通常 2 帧、十几笔就够。
- **完成，用于分析**：保存训练文件（数据旁边的 `<数据名>_vexel/brush/` 下），之后的预览和分析都用它识别液滴。**重新训练…** 可以继续修改。

它是一个像素分类器：每个像素按多尺度的亮度、边缘、纹理特征，用随机森林判断是液滴还是背景，再把液滴区域分开成一个个目标。训练文件只保存笔画周围的小块图像和笔画，每次运行按固定随机种子重新训练，所以同一配方 + 同一训练文件结果完全相同；配方里记录训练文件的 SHA-256，文件被改过会拒绝运行。

命令行：

```bash
uv run vexel brush my_video.avi -r droplet_encapsulation   # 画完后写出 <训练文件>.recipe.json
uv run vexel run my_video.avi -r data/my_video_vexel/brush/brush-20261114-101500.recipe.json
```

在线回放和监视文件夹同样可以用这个配方。

### 3.8 在线监控窗口

菜单 **文件 → 在线监控（回放录像 / 监视采集文件夹）…** 打开一个独立的看板窗口，也可以直接启动：

```bash
uv run vexel live                     # 打开看板
uv run vexel live my_video.avi        # 打开并选好要回放的录像
uv run vexel live D:/acquisition/run1 # 打开并选好要监视的文件夹
```

- **回放录像…**：把录好的视频按 **回放速度**（相对原始帧率，或“不限速”）一帧一帧送进来分析，就像相机实时送来一样（5.5 节）。
- **监视采集文件夹…**：采集软件每往文件夹里写一张图，就处理一张（5.6 节）。**无新图像结束** 秒数内没有新图像就结束；也可以在文件夹里放一个名为 `STOP` 的文件。结束后自动对整段采集再做一次全量分析，并在状态栏给出两者的液滴数。
- **分析** 选择液滴、包裹计数、荧光阴阳的组合；**像素尺寸**、**帧间隔** 同主窗口，按帧率回放需要帧间隔。

运行中：左边是当前帧（红线为液滴轮廓，每秒刷新约 4 次）；右边卡片是处理速度、丢帧数与占比（按帧率回放时另有延迟）、最近窗口内的液滴数、平均粒径与 CV、生成频率、λ 或阳性比例；下方三条滚动曲线（报警处有橙色虚线）；右下列出报警。**停止** 随时结束，已处理部分的结果照样保存。

结果保存在数据旁边的 `<数据名>_vexel/live-<时间>/`，格式与 5.5 节相同；**打开报告** 打开其中的 HTML 报告。

### 3.9 复核与纠错

自动分析总有出错的时候：重叠的细胞被少数、杂质被当成液滴、轮廓没找到。结果页右上角的 **复核与纠错…**（或命令 `uv run vexel review <结果文件夹>`）打开复核窗口，逐个检查并修正，然后按修正重算。原结果不会被改动。

- **左栏：液滴列表。** 默认只列“需要复核”的液滴（可疑液滴，见 6.7 节），并写明原因；也可以切换到“全部”或“已修改”。点一项就跳到该液滴所在的帧。
- **中间：当前帧。** 红线为轮廓，黄圈为检出的细胞，选中的液滴外有黄色圆圈。**放大选中** 打开时自动放大到选中的液滴，**上一帧 / 下一帧** 翻帧时跟着同一个液滴走。
- **工具：**
  - **选择**：点一个液滴，在右侧查看、修改。
  - **删除误检**：点一个轮廓，把它从这一帧的分割里删掉。
  - **补画**：按下拖动画一个圆，作为漏检的新目标。
  - **擦除**：按下拖动画一个圆，擦掉轮廓的这一部分。
  - **合并**：依次点两个轮廓，合成一个。
- **右栏：选中的液滴。** 包裹计数时可改 **细胞数**，荧光判读时可改 **阴阳性**，然后点 **保存修改**；自动结果正确时点 **确认无误**。**排除此液滴** 把整个液滴从统计中去掉（杂质、气泡、碎片）。人工改过或确认过的液滴不再列为可疑，计数不稳也不会被剔除。
- **修改记录** 列出所做的全部修改，**撤销最后一步** 逐条撤回。修改随时保存在结果文件夹的 `corrections.json` 里，关掉窗口下次还在。
- **应用并重算**：按全部修改重新运行同一配方，结果写入结果文件夹下的 `corrected/`，格式与原结果相同；报告里多一节“人工修正”，列出每条修改是否生效，方法段落也会注明。**打开修正后的报告** 查看。

轮廓修改只作用于所在的那一帧。一个液滴在很多帧里出现，要整个去掉时用 **排除此液滴**，不必逐帧删除。

命令行按已有的修改记录重算：

```bash
uv run vexel correct runs/exp01                         # 用 runs/exp01/corrections.json，写入 runs/exp01/corrected
uv run vexel correct runs/exp01 --corrections my.json -o runs/exp01-fixed
```

每条修改是否生效都会列出；有修改没找到目标时返回码为 1。修改记录的格式与设计见 [复核与纠错：设计说明](corrections.md)。在线回放或监视文件夹的结果也能修正：监视文件夹时用保存下来的 `frames.zarr` 重算，原采集文件夹可以已经删除。

### 3.10 批量分析与分组统计

要比较不同实验条件（流速比、表面活性剂、细胞浓度……）时，先在主窗口用一段录像把设置调好（预览确认液滴套得准），再点菜单 **文件 → 批量分析（多个文件、分组统计）…**。批量窗口用主窗口当前的全部设置分析每一个文件：

1. **选择文件夹…**：找出文件夹（含子文件夹）里的所有录像。按 `条件/芯片/录像` 的方式存放文件时，第一层子文件夹名自动填作 **组**，第二层填作 **重复**。也可以 **打开设计表…**（见 5.8 节）。
2. 在表里检查、修改 **组** 和 **重复**。“重复”指相互独立的芯片、批次或日期：同组同一重复的多个文件会先取平均，算作一个数据点。表里空着的像素尺寸和帧间隔用主窗口的值。
3. 选输出文件夹，点 **开始批量分析**。状态列逐个显示完成、失败或找不到文件；一个文件出错不会停下整个批量。随时可以 **停止**，之后用同一个输出文件夹再点开始，已完成的文件不会重算。
4. 完成后 **打开报告**：每个指标一张图（每个点是一个重复，横线为均值，竖线为 95% 置信区间）、各组描述统计、组间比较，以及每个文件自己的报告链接。

**保存设计表…** 把当前表格存成 CSV，可以在 Excel 里继续编辑，也可以用命令行 `vexel batch run` 运行。

## 5. 液滴模块：分析自己的数据

### 5.1 支持的输入

| 输入 | 说明 |
| :--- | :--- |
| `.tif` / `.tiff` | 多页 TIFF、OME-TIFF、ImageJ TIFF，可含多个通道。会读取文件里的像素尺寸、帧间隔和通道名称 |
| 图像序列目录 | 目录内的 `.tif` `.png` `.jpg` `.bmp`，每个文件一帧，尺寸必须一致，按文件名中的数字自然排序 |
| `.avi` `.mp4` `.mov` `.mkv` `.m4v` | 视频。帧间隔取自视频帧率；按 R、G、B 三个通道读入。彩色相机拍的荧光通常在其中一个颜色通道（如绿色荧光在 G，即通道 1） |
| `.npy` | 2 维按 YX、3 维按 TYX、4 维按 TCYX、5 维按 TCZYX 解释 |
| OME-Zarr 目录 | 例如 `vexel convert` 的输出 |

各通道分别存成不同文件（如明场一个视频、荧光另一个视频）的数据目前不支持，需要先合并成一个多通道文件。

### 5.2 先看元数据

```bash
uv run vexel info my_video.avi
```

```text
source   my_video.avi
reader   video
shape    {'T': 5000, 'C': 3, 'Z': 1, 'Y': 512, 'X': 1024}  uint8  (7864.3 MB)
spacing  y=1 x=1 z=1 px;  t=0.04 s
note     no pixel size found: results will be in pixels (pass --pixel-size to calibrate)
```

这一步不读像素，大文件也是立刻返回。重点看两处：帧数和尺寸是否符合预期；`spacing` 一行是否已有物理单位。

**注意：** 高速相机导出的视频，文件里的帧率通常是回放帧率（例如 25 fps），不是采集帧率。这种情况必须用 `--frame-interval` 指定真实的采集帧间隔，否则生成频率和速度都是错的。

### 5.3 标定

没有像素尺寸时，粒径以像素为单位输出，`summary.json` 中 `calibrated` 为 `false`。提供标定有三种方式，优先级从高到低：

1. 命令行参数：

   ```bash
   uv run vexel run my_video.avi -r droplet_basic --pixel-size 2.0 --frame-interval 0.001
   ```

   `--pixel-size` 的单位默认是 um，可用 `--unit` 改；`--frame-interval` 的单位是秒。

2. 旁挂文件。单个文件用 `<文件名>.vexel.json`（如 `my_video.avi.vexel.json`），图像序列目录用目录内的 `vexel.json`：

   ```json
   {"pixel_size": 2.0, "space_unit": "um", "frame_interval": 0.001}
   ```

3. 文件自带的元数据（OME-TIFF、ImageJ TIFF、视频帧率）。

### 5.4 运行

```bash
uv run vexel run my_video.avi -r droplet_basic --pixel-size 2.0 --frame-interval 0.001 -o runs/exp01
```

常用选项：

| 选项 | 作用 |
| :--- | :--- |
| `-r, --recipe` | 配方文件路径，或内置配方名 |
| `-o, --out` | 输出目录。省略时为 `runs/<输入名>-<配方名>-<时间戳>` |
| `--set 步骤.参数=值` | 临时覆盖配方参数，可重复使用 |
| `--max-frames N` | 只处理前 N 帧。调参时用它快速试 |
| `--keep-intermediates` | 保留每一步的中间数组（`scratch/` 下的 Zarr） |
| `--no-input-hash` | 不计算输入文件哈希。文件很大时可省时间，但溯源记录里就没有输入指纹 |
| `--overwrite` | 覆盖输出目录里的上一次运行 |
| `--workers N` | 逐帧算子使用的线程数，默认不超过 8 |

运行结束时会在输出目录里写一份 HTML 报告 `report.html`（见 6.8 节）。

输出目录非空时默认拒绝运行。加了 `--overwrite` 也只会覆盖 Vexel 自己的运行目录，不会删除其他内容。

### 5.5 在线回放

`vexel replay` 把录好的视频按原始帧率（或倍速）一帧一帧送进**流式执行器**，就像相机实时送来一样：边来边分析，定期给出滚动统计，指标漂移或超出质控范围时报警。用途是演示在线监控、测量软件的处理速度和丢帧率，以及在接相机之前检验配方能否跟上采集。

```bash
uv run vexel replay my_video.avi -r droplet_encapsulation --frame-interval 0.001 --speed 0.05
uv run vexel replay my_video.avi -r droplet_basic --speed max      # 不限速：测最大处理帧率
```

| 选项 | 默认 | 作用 |
| :--- | :--- | :--- |
| `--speed` | 1 | 相对原始帧率的倍速；`max` 为不限速。按帧率回放需要知道帧间隔（文件元数据或 `--frame-interval`） |
| `--queue` | 64 | 最多可排队等待处理的帧数 |
| `--update-every` | 50 | 每处理多少帧更新一次滚动统计 |
| `--window` | 500 | 滚动统计覆盖最近多少帧 |
| `--workers` | ≤ 8 | 积压时并行处理的帧数 |

其余选项（`-r`、`-o`、`--set`、`--max-frames`、标定）与 `run` 相同。运行中每次滚动更新打印一行，例如：

```text
  frame    199  19.86 fps  dropped 0  n 16  d 59.31  CV% 3.007  f 99.85  lambda 1.25
```

**它怎么做：**

- 逐帧算子（找圆、测量、数细胞、测荧光）与批式运行完全相同。
- 静态背景：先缓存开头 64 帧（`bg.max_frames`）求时间中值，之后每隔 2 帧取一帧放入滚动样本，每 32 帧重算一次。所以开头这些帧要等缓存满了才开始处理。
- 追踪：边来边连，流动位移的估计、截止距离、允许缺帧的规则与批式相同；一条轨迹超过允许的缺帧数没有再出现，就算结束。缺帧数和“轨迹至少几帧”（`droplets.min_track_frames`）都按轨迹跨越的帧数算，不按实际处理到的帧数算，所以隔帧处理不会把正常液滴丢掉。
- 汇总、泊松、阴阳判读、可疑液滴：就是批式的那几个算子。每 `--update-every` 帧在最近 `--window` 帧内已结束的轨迹上算一次（滚动统计），结束时在全部轨迹上再算一次，得到与 `run` 相同格式的 `summary.json` 和表格。

**跟不上时：** 按帧率回放而处理速度不够时，队列会积压。队列超过一半满时，改为每 2 帧处理 1 帧，仍积压就每 4、8、16 帧处理 1 帧（均匀抽样，被跳过的帧不会被读出）；队列快空时再逐级恢复。队列满时到达的帧直接丢弃。只要液滴穿过视野时仍能被处理到几次，轨迹就能连上、计数不受影响：在合成视频上，送帧为处理能力的 2 倍、跳过 60% 的帧时，液滴数和细胞数与全量分析完全一致。再快就会漏计，这时会报“处理能力”警报（见下）。抽样跳过的帧数、因队列满丢掉的帧数、每次调整抽样间隔的时刻都写进 `provenance.json` 的 `stream` 部分。不限速回放时不丢帧，队列满了就等待。

**报警（`stream/alarms.csv`，每条附当时画面 `stream/events/`）：**

- 质控：配方里表格类算子的质控规则（如 `flagged_fraction` 不超过 0.1），在滚动窗口填满之后逐次检查。
- 漂移：窗口内液滴数达到 20 个时，记下平均粒径和生成频率作为参照；之后平均粒径变化超过 5%、频率变化超过 15% 时报警。
- 处理能力：有帧因队列满被丢弃；或隔帧过多，按当前流速每个液滴穿过视野时只能被处理到不足 `droplets.min_track_frames`（3）次。出现这条警报时在线计数可能不全，应以全量分析为准（监视文件夹时会自动做）。
- 同一条警报持续存在时只报一次，恢复正常后再出现会再报。

**输出：** 与 `run` 相同（`summary.json`、`tables/`、`review/`、`report.html`、`provenance.json`），另有 `stream/rolling.csv`（每次滚动统计一行：帧号、收到/处理/丢弃帧数、处理帧率、延迟、各项指标）。报告里多一节“在线回放”：处理速度、丢帧、延迟、滚动曲线（报警处画竖线）和报警列表。`provenance.json` 的 `mode` 为 `stream`。

**速度：** 在 Apple M5 Pro 上不限速回放，512×104 的明场视频约 90 帧/秒，290×116 加细胞计数约 60 帧/秒，768×256 加细胞计数约 38 帧/秒。各送帧速率下的处理速度、丢帧率与一致性见 [第三阶段验收记录](phase3_acceptance.md)。这是软件本身的处理速度，**不含相机读出和传输**，不是端到端延迟。延迟（帧到达到处理完成）只在按帧率回放时记录；开头缓存背景的那些帧不计入。

**与批式运行的一致性：** 在合成数据和两段真实录像上，流式与批式计到的液滴相同，越线时刻相差不到 0.1 帧，细胞数一致（WSCNet 序列上至少 95% 的液滴相同，差别来自在线估计的背景略有不同），粒径相差在 1% 以内。

**限制：** 流式运行不输出可疑液滴的放大裁切图（结束时已不保存那些帧）；配方里只能有一个追踪步骤，静态背景必须直接读原始通道；数据源只有回放和监视文件夹，相机接入推迟到硬件对接阶段。

### 5.6 监视采集文件夹

采集软件把每一帧（或每一层）存成一个图像文件写进文件夹时，`vexel watch` 边采集边分析：

```bash
uv run vexel watch D:/acquisition/run1 -r droplet_encapsulation --pixel-size 2.0 --frame-interval 0.001
```

- **什么时候读一个文件：** 文件大小连续两次检查（每 `--poll` 秒，默认 0.2）都没变才读，避免读到写了一半的文件；以 `.` 开头的隐藏文件不读（很多软件先写临时名再改名）。支持 TIFF、PNG、JPEG、BMP；每个文件一帧，灰度或彩色（彩色按 RGB 三个通道）。
- **顺序：** 按文件名的自然顺序（`img_2` 在 `img_10` 之前）。
- **什么时候结束：** `--idle-timeout` 秒（默认 10）没有新文件；或文件夹里出现名为 `STOP` 的文件；或按 Ctrl-C。`--new-only` 忽略开始监视前已有的文件。
- **标定：** 命令行参数，或文件夹里的 `vexel.json`（如 `{"pixel_size": 2.0, "frame_interval": 0.001}`）。
- **存档：** 每一帧到达时追加写入输出目录下的 `frames.zarr`（OME-Zarr），采集结束时就是一个完整、带标定的数据集，可以用 `vexel run`、`vexel info` 直接读。`--no-zarr` 不存。
- **终算：** 采集结束后自动对 `frames.zarr` 再做一次批式全量分析，结果在输出目录的 `final/` 下，并打印在线与全量的液滴数。在线结果用于采集中的监控，`final/` 是正式结果。`--no-final` 跳过。

其余选项（`--queue`、`--update-every`、`--window`、`--workers`、`--set`）与 `replay` 相同；输出目录多一个 `frames.zarr` 和 `final/`。`provenance.json` 的 `stream.source` 记录监视的文件夹、收到的图像数和结束原因。

### 5.7 自动规划：探针、规划器与配方记忆

不知道该用哪个配方、哪些参数时，让 Vexel 先看数据、起草一个方案、在前几百帧上试跑，再交给你确认：

```bash
uv run vexel probe my_video.avi                          # 只看数据的“指纹”
uv run vexel probe my_video.avi --montage diag.png       # 另存一张四宫格诊断图
uv run vexel plan my_video.avi -g "数每个液滴里的细胞"     # 起草并试跑，写出 recipe.json
uv run vexel plan my_video.avi -g "ddPCR 阳性比例" --run   # 接受方案并分析全部帧
```

**探针**（`vexel probe`，几秒钟，不改任何数据）从均匀抽取的帧里算出：亮度范围、偏度、双峰分离度、噪声与信噪比、静止背景与运动区域的比例、流动方向与每帧位移（帧间相关）、静止背景的帧间抖动；在几帧上找圆和数斑点，得到液滴数、直径、圆度，以及液滴里是否有稳定的小深色斑点（细胞或珠子：提高阈值后数量基本不变的斑点；液滴内的反光、明暗会随阈值消失，不算）。多通道时判断哪个通道看液滴（亮背景、圆形运动目标），哪个是荧光（暗背景上的亮目标）。四宫格诊断图依次是：一帧、时间中值（背景）、时间标准差（运动区域）、找圆结果。

**规划器**（`vexel plan`）：

1. 从 `-g` 的文字里读出要测什么（中英文均可）：“细胞、包裹、珠子、泊松”表示数细胞，“荧光、阳性、ddPCR、digital”表示阴阳判读；“不数细胞”“不看荧光”表示不要。没说的按数据决定（看到稳定斑点就数细胞，有荧光通道就判读），并在理由里写明怎么取消。
2. 选内置配方，设好通道、流动方向等，每一项都附理由。默认的液滴识别不可信时（液滴在帧间几乎不动，或找到的是很多小颗粒），按尺寸扫描找出液滴直径，设定识别范围并关闭运动门控。
3. 在前 300 帧上试跑。没分割出目标就放宽找圆；没有液滴越过计数线就换流动方向、移动计数线；细胞计数不稳就提高细胞检测阈值；最多三轮，保留质控问题最少的一次。
4. 给出状态：**ready**（试跑通过全部质控规则）、**check**（能跑，但有质控提示，理由里列出）、**needs_user**（没有可用的分割，建议画笔训练；返回码 1）。

输出文件夹里有 `recipe.json`（可直接 `vexel run -r`）和 `plan.json`（指纹、理由、每次试跑的指标）。方案只是草案：加 `--run`，或自己用 `vexel run` 运行，才算接受。

**配方记忆**：用 `vexel plan --run` 运行过的方案会记下来（数据指纹、配方与设置、质控是否通过），存在 `~/.vexel/memory/recipes.jsonl`（环境变量 `VEXEL_HOME` 可改位置）。下次规划时，先按通道布局和分析类型硬过滤，再按标准化的指纹特征找最近的历史记录，显示其来源和历史通过率；足够接近且通过率不低于一半时，沿用它的设置并在理由里注明。`--no-memory` 既不用也不记。

**桌面界面**：载入数据后，在左栏“想测什么？”里写下目标（可以不写），点 **自动规划…**。几秒后弹出方案：状态、由谁起草、每条理由；点 **采用** 就把方案填进左侧设置（是否数细胞、是否判读荧光、通道、流动方向、高级设置），之后照常预览或分析。

**语言模型（可选）**：规划器可以请大语言模型帮忙理解目标、在试运行失败后再提一次建议。模型只能在一份白名单里提出设置（流动方向、计数线、找圆参数、细胞检测阈值等，每项有类型和范围），回答用 JSON 结构约束；不合格的建议被丢弃并写进理由，合格的照样试运行、由你确认。所有测量结果都由 Vexel 的算子计算，模型不产生数字。

可选的模型来源：

| 来源 | 默认模型 | 默认服务地址 | 密钥环境变量 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| Claude | `claude-opus-5-5` | Anthropic | `ANTHROPIC_API_KEY`（或 `ant auth login`） | 需 `uv sync --extra agent` |
| DeepSeek | `deepseek-chat` | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` | 服务器在中国大陆 |
| 通义千问（阿里云百炼） | `qwen-plus` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `DASHSCOPE_API_KEY` | 国际站账号改用 `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` |
| Google Gemini | `gemini-2.5-flash` | `https://generativelanguage.googleapis.com/v1beta/openai` | `GEMINI_API_KEY` | OpenAI 兼容接口 |
| 其他兼容服务 | 自填 | 自填 | 自填 `api_key_env` | 任何提供 OpenAI 风格 `/chat/completions` 的服务（如 vLLM、LM Studio、公司内网网关） |
| 本地模型 | 自填 | `http://localhost:11434` | 不需要 | Ollama，数据不离开本机/局域网 |
| 规则引擎 | – | – | 不需要 | 离线，总是可用，也是最后的退路 |

模型名会随服务商更新，以服务商当前的模型列表为准，可以在设置里改。**密钥只从环境变量读取，Vexel 不保存、不写入配置文件**；在 macOS/Linux 的 `~/.zshrc` 或 `~/.bashrc` 里写 `export DEEPSEEK_API_KEY=...`，Windows 用“系统属性 → 环境变量”，然后重新打开终端或 Vexel。

**在桌面界面里选择**（0.8 中为预览，需设置 `VEXEL_PREVIEW=1`；测试版默认只用离线规则，云端模型以后经 Vexel 网关提供）：帮助 → **规划模型设置…**。选模型来源，按需改模型名和服务地址，界面显示对应的密钥环境变量是否已设置；点 **测试连接** 发一次不含数据的小请求确认能用；**保存** 后，自动规划先问所选模型，不可用（没有密钥、断网、超时、拒答、答非所问）时自动改用规则引擎，方案里写明由谁起草、跳过了谁及原因。

**在命令行里选择**：`vexel plan --model claude|deepseek|qwen|gemini|custom|local|rules`（只试该来源，失败退回规则引擎）；`--model auto`（默认）按配置文件里的顺序。

配置文件 `~/.vexel/config.json`（`VEXEL_HOME` 可改位置），桌面界面保存的也是它：

```json
{"models": {"order": ["deepseek", "rules"],
            "deepseek": {"model": "deepseek-chat", "base_url": "https://api.deepseek.com", "api_key_env": "DEEPSEEK_API_KEY", "send_images": false},
            "custom": {"model": "my-model", "base_url": "http://gpu-box:8000/v1", "api_key_env": "", "send_images": false},
            "local": {"url": "http://localhost:11434", "model": "qwen2.5vl:7b", "send_images": false}}}
```

**数据与隐私**：默认只发：你写的目标、数据指纹里的数字（尺寸、亮度统计、流速、液滴数和直径等）、草案设置，以及试运行的汇总指标与质控提示。**不发图像、文件路径和逐个液滴的结果表**；`send_images: true` 时才附上降采样的四宫格诊断图（需要模型支持看图）。选用云端模型即表示这些数字会发到对应服务商，受其数据政策约束；数据不能出本单位时，用本地模型、内网兼容服务或规则引擎。设置环境变量 `VEXEL_OFFLINE=1` 只用规则引擎，不发出任何网络请求。

**MCP 服务**：`uv run vexel mcp` 以 stdio 方式提供 MCP 服务，让 AI 助手（如 Claude Desktop、Claude Code）调用 Vexel：`list_recipes`、`show_recipe`、`list_operators`、`probe_data`、`plan_analysis`、`run_analysis`、`read_results`。一切在本机运行，数据不经由它外传。在 Claude Desktop 的配置里加入：

```json
{"mcpServers": {"vexel": {"command": "uv", "args": ["--directory", "/path/to/Vexel", "run", "vexel", "mcp"]}}}
```

### 5.8 批量分析与分组统计

一个配方分析很多段录像，并按实验条件比较结果：

```bash
uv run vexel batch init data/exp01                       # 找出所有录像，写出设计表 data/exp01/design.csv
# 用 Excel 打开 design.csv，填写 group（条件）和 replicate（独立的芯片/批次/日期）
uv run vexel batch run data/exp01/design.csv -r droplet_encapsulation -o runs/exp01
uv run vexel batch run data/exp01 -r droplet_basic -o runs/quick   # 直接给文件夹：不分组，只汇总
```

**设计表**（CSV，每行一段录像；Excel 存的 UTF-8 或 GBK 都能读）：

| 列 | 含义 |
| :--- | :--- |
| `file` | 录像路径（视频、TIFF、图像序列文件夹、OME-Zarr），相对设计表所在文件夹或绝对路径。必填 |
| `group` | 实验条件，如 `比例1:2`。分组统计需要它 |
| `replicate` | 独立重复（芯片、批次、日期）。同组同一重复的多个文件先取平均；不填则每个文件算一个重复 |
| `pixel_size_um`、`frame_interval_s` | 这个文件的标定，覆盖文件自带的元数据 |
| `settings` | 只用于这个文件的设置，如 `droplets.flow_axis=y; seg.min_score=0.5` |
| `include` | 填 `no` / `否` 跳过这一行 |
| 其他列 | 原样保留，复制到结果表里（如培养基、操作者） |

`--set KEY=VALUE` 的设置作用于所有文件；`-r` 也可以是 `vexel plan` 写出的 `recipe.json`。

**无人值守与续跑**：每个文件单独分析，结果在 `<输出>/runs/<行号>_<名字>/`，与单次运行完全相同（表格、汇总、复核图、报告、溯源）。文件损坏、找不到、质控中止时记录原因并继续下一个；错误详情在 `runs/<行号>_<名字>.error.txt`。中途停止（Ctrl-C、关机）后再运行同一条命令，配方、设置、标定和输入文件（路径、大小、修改时间）都没变的已完成文件直接沿用，其余重新分析；`--no-resume` 全部重算。有文件没完成时返回码为 4。

**输出**：

| 文件 | 内容 |
| :--- | :--- |
| `results.csv` | 每个文件一行：设计表各列、状态、错误、质控提示数、结果摘要、全部汇总指标 |
| `replicates.csv` | 每个重复一行：组、包含的文件数、各指标（文件平均） |
| `groups.csv` | 每个指标 × 组：n、均值、标准差、标准误、均值的 95% 置信区间、中位数、最小、最大 |
| `comparisons.csv` | 组间比较：检验、p、Holm 校正后的 p、非参数检验 p、效应量、均值差及其 95% 置信区间 |
| `report.html` | 批量报告：每个指标的分组图与表、文件列表（链接到各自的报告）、中英文方法、溯源 |
| `methods_zh.txt`、`methods_en.txt` | 方法段落（中文、英文），可直接放进论文后修改 |
| `reproduce.py` | 复现脚本（见下） |
| `batch.json`、`recipe.json`、`design.csv` | 批量溯源：配方及其 SHA-256、设计表及其 SHA-256、每个文件的状态与结果摘要、软件环境 |

**统计方法**：同一段录像里的液滴不是相互独立的样本（同一芯片、同一次制备），拿几千个液滴直接比较会得到毫无意义的极小 p 值。所以统计**以重复为单位**：每段录像先得到一个汇总值（平均直径、CV、λ、阳性比例……），同一重复的录像取平均，再在重复之间比较。

- 两组：Welch t 检验（不假定方差相等），给出均值差及其 95% 置信区间、Hedges' g 效应量；另给 Mann–Whitney U 检验作不依赖正态假设的核对。
- 三组及以上：Welch 单因素方差分析与 Kruskal–Wallis 检验、η²；再两两 Welch t 检验，两两比较之间做 Holm 校正。
- 少于 2 个重复的组只作描述。只有 2 个重复时检验的把握很低，报告里会提示以效应量和置信区间为主。
- 液滴数（取决于录像长短）和可疑液滴比例（质控指标）只描述，不检验。
- 同一指标的单位不一致（有的文件标定了，有的没有）时不做检验，并提示。
- Holm 校正只在同一指标的两两比较之间；同时看很多指标时请谨慎解读。

**复现**：`python <输出>/reproduce.py [--out 新文件夹]` 在新的进程里用冻结的配方和设计表重新分析每一个文件、重算统计，并逐个核对结果摘要（全部表格与汇总的 SHA-256）是否与原来一致；全部一致时返回码为 0。脚本里列出了每个文件的路径、标定和设置，只依赖安装好的 Vexel（同一版本才能逐位一致）。

**桌面界面**：见 3.10 节。

| `volume_mean_pl`、`volume_cv_percent` | 平均液滴体积（pL）与体积 CV。未标定时为空 |
| `volume_model` | 体积按什么形状换算：`sphere` 球形；`flattened` 已填流道高度，压扁的液滴按压扁形状 |
| `channel_height_um`、`n_flattened` | 所填的流道高度，以及直径大于它、按压扁形状换算的液滴数 |

粒径是**等效面积直径**：与液滴分割区域面积相等的圆的直径。每个液滴取它完整出现在画面内的各帧的中位数。

**这是 2D 投影直径。** 体积由它换算：

- 不填流道高度，或液滴直径 D 不超过流道高度 h 时，按球形：V = πD³/6。
- D 大于 h 时，液滴被流道上下壁压扁，看成高为 h 的中央圆柱加一圈截面为半圆的环边：V = πa²h + π²h²a/4 + πh³/6，其中 a = (D − h)/2。两种算法在 D = h 时相同。

液滴被压扁却不填流道高度，体积会按球形算大，浓度随之偏小。流道高度以设计值或实测值为准，它的误差直接传递到体积。

### 6.5 包裹统计

使用 `droplet_encapsulation` 配方（或在界面中勾选包裹计数）时，`summary.json` 多出 `encapsulation.summary`。统计对象与 6.1 节相同：越过计数线、每个只计一次的液滴。

| 字段 | 含义 |
| :--- | :--- |
| `n_droplets` | 参与包裹统计的液滴数 |
| `n_inclusions_total` | 细胞总数 |
| `lambda` | 平均每滴细胞数 λ（泊松参数的最大似然估计） |
| `lambda_ci_low` / `_high` | λ 的 95% 精确置信区间（按细胞总数的泊松区间） |
| `frac_empty` / `frac_single` / `frac_multi` | 实测的空滴（0 个）、单包裹（1 个）、多包裹（≥2 个）比例 |
| `poisson_empty` / `_single` / `_multi` | 同一 λ 下泊松分布的预期比例：e^−λ、λe^−λ、其余 |
| `single_among_occupied` | 有细胞的液滴中单包裹所占比例，即单细胞包裹的纯度 |
| `variance`、`dispersion_index` | 计数的样本方差，离散指数 D = 方差 ÷ λ。泊松分布时 D ≈ 1 |
| `chi2`、`chi2_dof`、`chi2_p` | 实测分布对泊松分布的卡方拟合优度检验。预期数不足 5 的相邻类别会合并；类别太少时为空 |
| `n_low_agreement` | 各帧计数一致率低于 0.8 的液滴数 |
| `inclusions_per_ul`、`_ci_low`、`_ci_high` | 细胞浓度（个/µL）= λ ÷ 平均液滴体积，及其区间。区间只反映计数统计，不含体积误差 |
| `n_excluded` | 无法计数（液滴内部区域太小）而未计入的液滴数 |

**怎么读：**

- 细胞随机上样时，包裹数应服从泊松分布。`chi2_p` 小于 0.05 表示实测分布与泊松分布差异显著。
- D 明显大于 1：细胞聚集、成团或上样浓度随时间漂移。D 明显小于 1：排布比随机更规则（例如惯性有序包裹）。
- `n_low_agreement` 不为 0 时，这些液滴的计数可能不准，先在复核图中核对，再看统计结论。

**计数方法：** 被画面边缘截断的液滴不计。每一帧里，每个液滴以它自己的径向灰度剖面作背景（`background: radial`）：中心 60% 半径内取一个中位灰度，外圈逐个半径取中位数，这样液滴的暗环、亮边、透镜效应都被扣掉；再按 8 个扇区找出暗环从哪个半径开始（暗环常常一侧厚一侧薄），只在暗环以内数，另外离液滴边缘 `edge_margin_px` 个像素以内不计。平滑后比背景暗（或亮）超过阈值的局部极值记为一个细胞。阈值默认自动：从液滴内部估计噪声水平，取平滑后噪声的 6 倍（`noise_factor`），因此 8 位和 16 位图像都适用；一帧里有明显的细胞时，还要求达到它们中位对比度的 30%（`relative_floor`），用来排除干净图像里的浅色阴影。两个细胞贴在一起时，平滑后可能只剩一个峰：一个斑点的范围（对比度不低于其峰值一半的区域）约为同一帧典型斑点的 2 倍或 3 倍、且强度不低于该帧最强斑点的一半时，按 2 个或 3 个计（`split_touching`，默认开启；较弱的大片阴影不会被拆分）。每个液滴最终取它完整出现在画面内的各帧计数的众数。

在真实数据（WSCNet2 示例序列，134 个液滴，人工数细胞）上：空液滴全部判对，132 个确定的液滴中 5 个数错（96%），都是细胞前后重叠、多数帧里看起来是一个而少数；λ 测得 1.52，人工 1.57。另一段真实数据（珠子包裹）的评估见 [液滴内计数评估](eval_cell_counting.md)。

### 6.6 荧光阴阳判读

使用 `droplet_fluorescence` 或 `droplet_fluorescence_encapsulation`（或在界面中勾选荧光）时，`summary.json` 多出 `positivity.summary`。统计对象同样是越过计数线、每个只计一次的液滴。

| 字段 | 含义 |
| :--- | :--- |
| `n_droplets`、`n_positive` | 参与判读的液滴数与阳性数 |
| `positive_fraction` | 阳性比例 p |
| `positive_fraction_ci_low` / `_high` | p 的 95% Wilson 置信区间 |
| `copies_per_droplet` | 每滴平均拷贝数 λ = −ln(1 − p)，即数字 PCR 等数字检测的泊松校正。全部阳性时无法估计，为空 |
| `copies_ci_low` / `_high` | 由 p 的置信区间换算得到的 λ 区间 |
| `copies_per_ul`、`_ci_low`、`_ci_high` | 液滴中的浓度（拷贝/µL）= λ ÷ 平均液滴体积，及其区间。区间只反映计数统计，不含体积误差；未做稀释换算 |
| `threshold` | 阳性阈值（`fluo_mean` 高于它为阳性） |
| `threshold_method` | 阈值的确定方式：`mixture` 自动分群、`outlier` 离群值规则、`fixed` 固定值、`otsu` 大津法 |
| `populations` | 自动判读认定的群数：2 为阴阳两群，1 为只有一群 |
| `separation_d` | 阴阳两群的分离度（Ashman's D）。D ≥ 4 时两群分得很开；2–4 有重叠；小于 2 基本分不开 |
| `dip_ratio` | 两群之间密度低谷的深度（低谷高度 ÷ 较矮的峰高）。越小越清楚 |
| `negative_mean`、`positive_mean` | 两群的平均荧光 |
| `saturated` | 是否全部为阳性 |

**自动阈值怎么定（`method: auto`）：** 下面两项同时成立，才认定存在阴阳两群，并取两群概率相等处为阈值：

1. 两成分高斯混合模型的 BIC 比单成分低 10 以上（`min_bic_gain`）；
2. 两群确实分开，满足其一：
   - 两群之间的密度有明显低谷（`dip_ratio` 小于 0.6，`max_dip_ratio`），且分离度 D 不小于 3（`min_separation`）；
   - 分离度 D 不小于 3.6（`strong_separation`），且低谷比小于 0.8（`strong_max_dip_ratio`）。第二条照顾阳性液滴间差异大、低谷较浅、但两群显然分开的情况。

单靠 BIC 不够：荧光强度常呈偏态，而液滴一多，混合模型几乎总会把一个偏态的单峰拆成两群。低谷和分离度这两项正是用来挡住这种误拆。

否则视为只有一群，用离群值规则判读：高于中位数加 6 倍稳健标准差（`outlier_k`）的液滴才判为阳性。这样全阴性样本（如无模板对照）不会被硬拆出假阳性。代价是：如果所有液滴都是阳性，或阴阳两群严重重叠，自动判读会全部判为阴性，结果页和 `populations = 1` 会提示。此时应该用阴性和阳性对照确定阈值，改用固定阈值。

**在合成数据上的表现：**

| 条件 | 结果 |
| :--- | :--- |
| 阴阳分得开（阳性约为阴性的 4 倍以上，液滴间差异 10%），阳性比例 1%–97% | 每个液滴都判对 |
| 同上，荧光噪声加大到 10 个灰度级 | 每个液滴都判对 |
| 阳性的液滴间差异 30%（两群边缘重叠） | 两组 200 个液滴：一组错 2 个（1%），一组全对 |
| 全阴性，液滴间差异 10% 或 30% | 无假阳性 |
| 阳性只比阴性亮 1.6 倍且差异 20%（两群严重重叠） | 自动判读认定只有一群，全部判阴性并给出提示；需要固定阈值 |

另用随机数检验了自动判据（每种情形 120 次）：

- 单峰分布（正态、伽马、对数正态，含明显偏态）：200 个液滴以上时误拆成两群的比例为 0–1%，40 个液滴时最多约 3%；
- 分得开的两群（阳性占 2%–95%）：200 个液滴以上检出率 95%–100%；
- 阳性液滴间差异 30% 的两群：200 个液滴时检出率 97%，500 个以上为 100%，40 个液滴时只有约 60%。

液滴少于约 40 个时，自动判读更倾向于“只有一群”。

### 6.7 可疑液滴

每个配方的最后一步 `flags` 逐个检查液滴，把需要人工确认的列入 `flags.table.csv`，并在 `review/flags/` 下为每个写一张放大的裁切图（最多 48 张），图上同样画出轮廓与细胞标记。`summary.json` 的 `flags.summary` 给出总数与各原因的个数。

| 原因 | 判据（参数） | 含义 |
| :--- | :--- | :--- |
| 形状不圆 `low_circularity` | 圆度小于 0.85（`min_circularity`） | 可能是两个液滴粘连、碎片或气泡 |
| 粒径异常 `size_outlier` | 偏离中位数超过 4 个稳健标准差（`size_outlier_k`） | 合并液滴、卫星液滴或分割错误 |
| 计数不稳 `count_unstable` | 细胞数的帧间一致率低于 0.8（`min_inclusion_agreement`） | 细胞数可能数错 |
| 近阈值 `near_threshold` | `call_margin` 绝对值小于 0.1（`threshold_margin`） | 阴阳判读最不确定 |
| 帧数少 `few_frames` | 在视野中停留的帧数（从首次出现到最后出现）不到中位数的一半（`min_frames_fraction`）。按跨度而不是被处理到的帧数算，所以在线回放隔帧处理时不会误报 | 测量依据少；多为轨迹断开或刚进出视野 |

裁切图取该液滴最接近计数线、且完整在画面内的那一帧。可疑液滴超过 10% 时，质控规则给出警告。

在合成数据上的检验：一段 1500 帧、细胞对比度很低且噪声大的视频里，数错细胞的 11 个液滴全部被列为“计数不稳”；阴阳判错的 2 个液滴里，有 1 个荧光完全落在阴性群内部（真值为阳性，是合成时液滴间差异的低尾），任何基于荧光强度的方法都无法把它挑出来。

### 6.8 HTML 报告

每次运行结束，输出目录里会生成 `report.html`。它是单个文件，样式、图表与图片都内嵌其中，可以直接发邮件或存档，用浏览器打开，也可以打印。内容依次为：

1. 概况与提示（与界面结果页的提示相同）；
2. 关键结果：液滴、包裹、荧光；
3. 图表：粒径分布、包裹数分布、粒径与荧光；
4. 复核图与可疑液滴图集；
5. 方法：按冻结的配方自动生成的中文方法段落，含各步参数与软件版本，可作为论文方法部分的初稿；
6. 溯源：输入文件与哈希、标定、配方哈希、结果摘要、各步骤耗时与质控指标、软件版本。

报告是由同一文件夹里的结果文件生成的视图，不计入 `result_digest`。以后改了报告样式，或者想重新生成，可以用：

```bash
uv run vexel report runs/exp01
```

报告里的“输入文件”一项会写出数据在本机的完整路径；对外发送前请留意。

## 7. 配方

配方是一个 JSON 文件，描述分析的每一步。它在运行前被校验并冻结，运行中不会改变。

### 7.1 查看内置配方

```bash
uv run vexel recipes
uv run vexel recipes --show droplet_basic
```

内置四个配方：

| 配方 | 内容 |
| :--- | :--- |
| `droplet_basic` | 液滴粒径、计数与生成频率 |
| `droplet_encapsulation` | 再加包裹计数与泊松统计 |
| `droplet_fluorescence` | 再加荧光强度与阴阳判读（不含包裹计数） |
| `droplet_fluorescence_encapsulation` | 以上全部 |

四个配方中同名的步骤参数完全相同，只是组合不同。每个配方的最后一步都是 `flags`（`droplet.flags`），列出需要人工确认的液滴（见 6.7 节）。

`droplet_basic` 的五个步骤：

| 步骤 id | 算子 | 作用 |
| :--- | :--- | :--- |
| `bg` | `preprocess.static_background` | 用时间中值估计静态背景（流道壁、不均匀照明）并扣除 |
| `seg` | `segment.circles` | 找圆形液滴：显示为细暗环、亮心或实心的液滴都能识别，相互接触的液滴分开 |
| `measure` | `measure.regionprops` | 测量每个目标的位置、面积、粒径、圆度 |
| `track` | `track.link` | 把逐帧检测连成轨迹 |
| `droplets` | `droplet.summary` | 按计数线去重，输出每液滴表和汇总统计 |

`droplet_encapsulation` 多两步，并让 `droplets` 步骤接收细胞计数：

| 步骤 id | 算子 | 作用 |
| :--- | :--- | :--- |
| `inclusions` | `droplet.inclusions` | 逐帧数每个液滴里的细胞，并输出细胞标记供复核图使用 |
| `encapsulation` | `droplet.poisson` | 汇总包裹数分布，与泊松分布比较 |

细胞在 `input.channels.cells` 通道里数，默认与分割通道相同（0）。

`droplet_fluorescence` 在 `droplet_basic` 基础上多两步：

| 步骤 id | 算子 | 作用 |
| :--- | :--- | :--- |
| `intensity` | `droplet.intensity` | 在荧光通道（`input.channels.fluo`，默认 1）逐帧测每个液滴的荧光 |
| `positivity` | `droplet.positivity` | 判读每个液滴的阴阳性，汇总阳性比例与每滴拷贝数 |

### 7.2 配方结构

```json
{
  "schema_version": 1,
  "name": "my_recipe",
  "description": "说明文字",
  "seed": 0,
  "input": {"channel": 0, "z": 0},
  "steps": [
    {
      "id": "seg",
      "op": "segment.threshold_watershed",
      "inputs": {"image": "bg.image"},
      "params": {"min_area": 100},
      "qc": [{"metric": "n_objects.max", "min": 1, "on_fail": "warn"}]
    }
  ],
  "review": {"image": "source", "labels": "seg.labels", "n_frames": 4}
}
```

- `input`：分析哪个通道、哪个 z 平面。`channel` 是 `source`；`channels` 给其他通道起名，例如 `"channels": {"fluo": 1}` 后，步骤里用 `"source.fluo"` 引用通道 1。这样可以在一个通道分割、在另一个通道测量。通道号从 0 起。
- `steps`：按顺序执行。`id` 只能用小写字母、数字、下划线，且以字母开头。
- `inputs`：每个输入接到哪里。`"source"` 是原始图像，其余写成 `"步骤id.输出名"`，只能引用前面的步骤。
- `params`：省略的参数取默认值。写错参数名会报错，不会被悄悄忽略。
- `qc`：可选的质控规则，见 7.4。
- `review`：可选，指定复核图用哪个图像（`image`）和哪个分割结果（`labels`，红线）；`marks` 可再指定一组标记（黄圈），如检出的细胞。

运行前会检查：算子是否存在、接线的数据类型是否匹配（图像 / 标签 / 表格 / 汇总）、参数是否合法。

### 7.3 修改参数

临时修改用 `--set`：

```bash
uv run vexel run my_video.avi -r droplet_basic --set seg.min_score=0.5 --set droplets.count_line=0.4
```

需要长期使用时，导出内置配方再编辑：

```bash
uv run vexel recipes --show droplet_basic > my_recipe.json
uv run vexel run my_video.avi -r my_recipe.json
```

通道也用 `--set` 改，不必编辑配方：

```bash
uv run vexel run my_video.avi -r droplet_fluorescence --set input.channels.fluo=1
uv run vexel run my_stack.tif -r droplet_fluorescence_encapsulation --set input.channels.cells=1 --set inclusions.polarity=bright
```

实际使用的全部参数（含默认值）都写在输出目录的 `recipe.json` 里。

### 7.4 质控规则

每个算子会输出质控指标，记录在 `provenance.json` 的 `steps[].qc` 中。可以在配方里给指标设上下限：

```json
"qc": [{"metric": "foreground_fraction.max", "max": 0.6, "on_fail": "warn"}]
```

- 逐帧算子的指标按时间聚合，写成 `指标名.mean`、`指标名.min`、`指标名.max`。
- 跨帧算子的指标直接用指标名。
- `on_fail` 为 `warn` 时只提示并继续；为 `stop` 时中止运行，已完成的结果和溯源记录仍会保存，命令返回码为 3。

各算子的指标：

| 算子 | 指标 |
| :--- | :--- |
| `preprocess.static_background` | `frames_sampled`、`background_mean`、`residual_mean` |
| `segment.circles` | `n_objects`、`radius_median_px`、`score_median`、`foreground_fraction`（各带 `.mean/.min/.max`） |
| `segment.threshold_watershed` | `threshold`、`n_objects`、`foreground_fraction`（各带 `.mean/.min/.max`） |
| `measure.regionprops` | `n_objects`（带 `.mean/.min/.max`） |
| `track.link` | `n_tracks`、`mean_track_length`；估计流动时另有 `flow_dy_px`、`flow_dx_px`（每帧位移的中位数） |
| `droplet.summary` | `n_droplets`、`diameter_cv_percent`、`circularity_median` |
| `droplet.inclusions` | `n_inclusions`、`contrast_threshold`（各带 `.mean/.min/.max`） |
| `droplet.poisson` | `n_droplets`、`dispersion_index`、`chi2_p`、`low_agreement_fraction` |
| `droplet.intensity` | `background`、`droplet_mean`（各带 `.mean/.min/.max`） |
| `droplet.positivity` | `n_droplets`、`positive_fraction`、`separation_d` |
| `droplet.flags` | `n_flagged`、`flagged_fraction` |
| `stats.describe` | `n` |

`droplet_encapsulation` 默认对 `low_agreement_fraction` 设了上限 0.1：计数不稳定的液滴超过 10% 时给出警告。荧光配方默认要求 `separation_d` 不小于 2，否则警告阴阳两群分不开。所有配方默认对 `flagged_fraction` 设上限 0.1。

## 8. 调参指南

先用 `--max-frames 200` 快速试，看复核图，再跑全量。

| 现象 | 调整 |
| :--- | :--- |
| 没有液滴的地方出现圆 | 调高 `seg.min_score`（如 0.5）；或调高 `seg.motion_threshold` |
| 液滴漏检 | 调低 `seg.min_score`（如 0.25）；或调低 `seg.motion_threshold` |
| 小卫星液滴、碎片被当成液滴 | 设定 `seg.min_diameter_px`（像素）；默认只保留与每帧中位大小相差 30% 以内的圆（`seg.size_tolerance`） |
| 液滴大小差别很大（多分散） | 同时设定 `seg.min_diameter_px` 和 `seg.max_diameter_px`，并把 `seg.size_tolerance` 设为 `null` |
| 液滴不是圆形（长条塞子、被挤变形） | 圆检测不适用。导出配方，把 `seg` 步骤换成 `segment.threshold_watershed`（输入接 `bg.image`），见第 9 节 |
| 同一液滴被数成多个（`n_tracks_total` 远大于实际） | 调高 `track.max_distance_px`；它应大于液滴每帧位移的变化量 |
| 不同液滴被连成一条轨迹 | 调低 `track.max_distance_px` |
| 每帧位移接近或大于液滴间距的一半 | 内置配方默认按每帧的检测位置估计整体流动并扣除（`track.estimate_shift`），一般不用调；查看 `provenance.json` 里的 `flow_dx_px` 是否与实际相符。估计不对时设 `estimate_shift=false` 并给出 `track.expected_shift_px`，例如 `--set 'track.expected_shift_px=[0,25]'` |
| 液滴沿竖直方向流动 | `--set droplets.flow_axis=y` |
| 液滴不动或在帧间几乎不动（从视频里抽出的帧、停流、静态阵列），默认找到的是很多小圆 | 给出液滴直径范围并关闭运动门控：`--set seg.min_diameter_px=<像素> --set seg.max_diameter_px=<像素> --set seg.motion_threshold=0 --set seg.min_score=0.5`。自动规划会识别这种情况并自动设置（5.7 节）。液滴不流动时跨帧去重计数不适用 |
| 计数线处有遮挡或流道结构 | 调整 `droplets.count_line`（0 到 1 之间，沿流动方向的比例位置） |
| 背景扣除后液滴残影明显 | 液滴过密，同一像素超过一半时间被液滴覆盖，时间中值不再是背景。调高 `bg.max_frames`；仍不行则该方法不适用 |
| 细胞漏数（复核图中细胞没有黄圈） | 设定 `inclusions.min_contrast` 为一个较小的固定值（参考 `provenance.json` 中 `contrast_threshold.mean` 的自动值，从它的一半试起）；或调低 `inclusions.noise_factor` |
| 空液滴里数出细胞（噪点、杂质被圈出） | 设定 `inclusions.min_contrast` 为一个较大的固定值；或调高 `inclusions.noise_factor` |
| 压缩过的视频（JPEG、MP4、缩放过）里，液滴轮廓内侧的阴影、小杂质被大量数成细胞 | 自动阈值按噪声定，压缩视频的噪声估计偏低。依次调高 `inclusions.noise_factor`（如 15、25、40）、`inclusions.relative_floor`（如 0.6）、`inclusions.edge_margin_px`（如 6），在复核图上确认；一段珠子视频上这样调到留出帧 87% 完全正确（见 [液滴内计数评估](eval_cell_counting.md)） |
| 很小的杂质点被数成细胞 | 设 `inclusions.min_size_fraction`（如 0.5）：范围小于一个细胞面积这一比例的斑点不计 |
| 两个紧挨的细胞被数成一个 | 默认按斑点大小拆分（`inclusions.split_touching`）；仍不够时调小 `inclusions.cell_diameter_px`，或设定 `inclusions.min_separation_px` |
| 细胞被错误地拆成两个（细胞大小差别很大） | `--set inclusions.split_touching=false` |
| 一个细胞被数成两个 | 调大 `inclusions.cell_diameter_px` |
| 贴近液滴边缘的细胞漏数 | 调小 `inclusions.edge_margin_px`；暗环本身由扇区检测排除，紧贴暗环的细胞仍会被一并排除 |
| 一帧里只有暗淡细胞时漏数 | `inclusions.relative_floor` 只在有明显细胞的帧里生效；仍漏数时设为 0 |
| 细胞比液滴内部亮（荧光） | `--set inclusions.polarity=bright` |
| 液滴被流道压扁（俯视直径大于流道高度） | 填写流道高度：`--set droplets.channel_height_um=<µm>`（界面：设置 › 流道高度），否则体积按球形算大、浓度偏小 |
| 可疑液滴太多（质控提示 `flagged_fraction` 超限） | 看 `flags.summary` 里哪一类最多，按对应的行调整；某类判据对你的数据过严时，可放宽 `flags` 的对应参数 |
| 荧光提示“只发现一群液滴”，但样本应含阳性 | 用阳性和阴性对照确定阈值，`--set positivity.threshold=<值> --set positivity.method=fixed`（界面：高级设置 › 阳性阈值） |
| 全阴性对照里出现少量阳性 | 多为荧光离群液滴（气泡、杂质）。核对复核图；必要时用固定阈值 |
| 荧光阴阳两群重叠（D 小于 4） | 检查荧光通道是否选对、曝光是否合适；必要时调大 `intensity.edge_margin_px` 避开液滴边缘 |
| 荧光背景不均匀 | `intensity.background` 取液滴外像素的中位数作背景；背景很不均匀时可设为 `none`，并用固定阈值 |

**关于粒径偏差：** 圆检测把半径定在液滴外缘（扣除背景后的对比度下降最快处）。在合成数据上粒径均值偏小约 0.7%；在一段带 50 µm 比例尺的真实视频上测得 52.3 µm，与目测外缘约 50 µm 一致。明场下液滴的“边界”本身取决于成像（暗环有几个像素宽），对绝对粒径有要求时，应该用已知尺寸的样品或人工标注做一次校准（见第 10 节）。

## 9. 算子参考

完整且最新的列表以命令输出为准：

```bash
uv run vexel ops
```

**作用范围**决定算子一次需要看到多少数据：`frame` 逐帧独立处理；`window` 需要时间轴上的多帧。

| 算子 | 范围 | 输入 → 输出 | 说明 |
| :--- | :--- | :--- | :--- |
| `preprocess.static_background` | window | 图像 → 图像 | 时间中值背景扣除。`mode`：`absdiff`（默认，亮暗目标都变亮）、`subtract`、`divide` |
| `preprocess.background_correction` | frame | 图像 → 图像 | 单帧背景校正：顶帽或大尺度高斯。适用于没有稳定静态背景的数据 |
| `preprocess.gaussian` | frame | 图像 → 图像 | 高斯平滑 |
| `preprocess.median` | frame | 图像 → 图像 | 中值去噪 |
| `segment.circles` | frame | 图像 + 对比度图像 → 标签 | 内置配方使用。在原始图像上取边缘（只取对比度图像显示有东西的地方），Hough 变换找圆，去重叠，按每帧典型大小筛选，圆心以边缘点拟合精修，半径定在液滴外缘。适用于圆形液滴，不论显示为细暗环、亮心还是实心 |
| `segment.pixel_classifier` | frame | 图像 → 标签 + 概率图 | 画笔训练得到的像素分类器（随机森林，多尺度亮度、边缘、纹理特征）。参数 `training` 为训练文件，`training_sha256` 为其哈希 |
| `segment.threshold_watershed` | frame | 图像 → 标签 | 阈值（`otsu` / `triangle` / `fixed`）+ 填洞 + 开运算 + 分水岭分离。适用于非圆形目标 |
| `measure.regionprops` | frame | 标签（+ 可选强度图像）→ 表格 | 位置、面积、等效直径、长短轴、偏心率、圆度、平均强度 |
| `track.link` | window | 表格 → 表格 | 线性指派追踪，增加 `track_id` 列。`estimate_shift` 时先由检测位置估计逐帧流动位移并扣除，液滴排成密集长队、每帧移动接近间距一半时也能连对 |
| `stats.describe` | window | 表格 → 汇总 | 某一列的 n、均值、标准差、CV、中位数、范围 |
| `droplet.summary` | window | 表格（+ 可选细胞计数表、荧光表）→ 表格 + 汇总 | 计数线去重、粒径统计、体积、生成频率、速度、间距；有细胞计数表时为每个液滴给出细胞数，有荧光表时给出荧光 |
| `droplet.inclusions` | frame | 图像 + 标签 → 表格 + 标签 | 数每个液滴内的细胞（暗点或亮点），输出每帧计数和细胞标记。`background`：`median`（每滴一个背景值）或 `radial`（每滴自己的径向剖面，内置配方使用） |
| `droplet.poisson` | window | 表格 → 表格 + 汇总 | 包裹数分布、λ、空滴/单包裹/多包裹比例、泊松预期、离散指数、卡方检验 |
| `droplet.intensity` | frame | 图像 + 标签 → 表格 | 每个液滴扣除背景后的平均、中位、第 95 百分位与积分荧光 |
| `droplet.positivity` | window | 表格 → 表格 + 汇总 | 阴阳判读（自动分群 / 离群值规则 / 大津法 / 固定阈值）、阳性比例、每滴拷贝数与浓度 |
| `droplet.flags` | window | 每液滴表 + 每帧轨迹表 → 表格 + 汇总 | 列出需要人工确认的液滴、原因与查看帧 |

## 10. 用真值验证

`vexel validate` 把一次运行的汇总结果与真值比对，所有检查项都在容差内才算通过。基本检查五项：液滴数、粒径均值、粒径 CV、生成频率、平均体积（真值体积按同一流道高度由真值粒径换算）。运行做了包裹计数且真值带细胞数时，另加五项：逐液滴细胞数错误率、λ、空滴比例、单包裹比例、多包裹比例。运行做了荧光判读且真值带阴阳性时，再加两项：逐液滴判错率、阳性比例。

```bash
uv run vexel validate runs/exp01 --truth path/to/truth
```

| 选项 | 默认 | 含义 |
| :--- | :--- | :--- |
| `--count-tol` | 0 | 液滴数允许的绝对误差 |
| `--diameter-tol` | 0.02 | 粒径均值允许的相对误差 |
| `--cv-tol` | 1.0 | CV 允许的绝对误差，百分点 |
| `--frequency-tol` | 0.02 | 生成频率允许的相对误差 |
| `--volume-tol` | 0.06 | 平均体积允许的相对误差（体积随粒径的三次方变化，约为粒径容差的 3 倍） |
| `--mismatch-tol` | 0.05 | 细胞数数错的液滴允许占的比例 |
| `--lambda-tol` | 0.05 | λ 允许的相对误差 |
| `--fraction-tol` | 0.03 | 空滴、单包裹、多包裹比例允许的绝对误差 |
| `--positive-mismatch-tol` | 0.02 | 阴阳判错的液滴允许占的比例 |
| `--positive-fraction-tol` | 0.03 | 阳性比例允许的绝对误差 |

**默认容差是占位值**，尚未与实际使用方约定。

### 给真实数据做标注

真值目录需要三个文件，格式与合成数据的 `truth/` 相同：

`droplets.csv`，每个液滴一行：

```text
droplet_id,diameter_um
0,58.2
1,60.1
```

要验证包裹计数，再加一列 `n_cells`（该液滴里的细胞数）；要验证荧光判读，再加一列 `positive`（`True` / `False`）。例如：

```text
droplet_id,diameter_um,n_cells
0,58.2,1
1,60.1,0
```

`positions.csv`，每个液滴在每一帧的中心 x 坐标（像素）：

```text
frame,droplet_id,x_px
0,0,120.5
1,0,131.0
```

`config.json`：

```json
{"frame_interval_s": 0.001}
```

比对时会用与分析相同的计数线和帧范围，从 `positions.csv` 算出哪些液滴越线，再比较这些液滴的数量、粒径均值、CV 和频率。细胞数按液滴逐个比对：测得的液滴与真值液滴按越线时刻配对（相差不超过 1 帧），再看细胞数是否相同。

限制：运行必须已标定为 um；目前只支持沿 x 方向流动的数据。

### 生成不同条件的合成数据

```bash
uv run vexel synth data/noisy --frames 1000 --noise 8 --diameter 40 --cv 5 --frequency 180 --seed 3
```

| 选项 | 默认 | 含义 |
| :--- | :--- | :--- |
| `--frames` | 400 | 帧数 |
| `--diameter` | 60 | 平均粒径，um |
| `--cv` | 3 | 粒径 CV，% |
| `--frequency` | 100 | 生成频率，Hz |
| `--noise` | 3 | 相机噪声标准差，灰度级 |
| `--cells` | 0 | 平均每滴细胞数 λ，按泊松分布放入细胞；0 为不放细胞 |
| `--fluo` | 不加 | 加一个荧光通道，数值为每滴平均拷贝数；含 1 个及以上拷贝的液滴为阳性 |
| `--cells-in` | brightfield | 细胞出现在哪个通道：`brightfield`（明场暗点）或 `fluorescence`（荧光亮点，需要 `--fluo`） |
| `--seed` | 0 | 随机种子 |

合成视频固定为 256×768、2 um/像素、1 ms/帧、流速 20 mm/s。加 `--fluo` 时为两通道 OME-TIFF（通道 0 明场、通道 1 荧光）：油相背景 8，阴性液滴 25，阳性液滴 120，液滴间差异 10%，噪声 3 个灰度级；明场通道与不加荧光时逐像素相同。细胞为直径 10 µm（5 像素）的深色圆点，比液滴内部暗 50 个灰度级，随液滴平移，彼此至少相隔 1 个像素。它是理想化的：液滴为正圆、匀速、不粘连、轮廓清晰；细胞形状一致、不转动、不贴边。**在合成数据上通过不代表在真实数据上准确。**

在合成数据上的包裹计数准确度（每组 40 个液滴，共 14 组）：λ 从 0.3 到 3、噪声 3 到 12 个灰度级、细胞对比度低至 15 个灰度级时，逐液滴细胞数全部正确；只有细胞对比度 15 且噪声 6 时（信噪比约 2.5），40 个液滴中有 3 个数错，且这 3 个的帧间一致率都低于 0.4。

### 11.2 打开图片与标定

支持 TIFF、PNG、JPEG、BMP，单张最多 1 亿像素（例如 10000×10000）；更大的通常是拼接的大图，会提示先裁出要测量的区域。请使用**仪器保存的原始文件**：截图、重新保存的 JPEG、裁掉信息栏的图片会丢失标定所需的信息。Hitachi 与 JEOL 把参数写在同名的 `.txt` 文件里，TESCAN 有时写在 `.hdr` 文件里，**复制图片时要连同这些文件一起复制**。

标定按顺序尝试三种来源，**结果总是写明来源与是否经人确认**：

1. **仪器元数据**（可信度高，自动采用）：Thermo Fisher（FEI）与 Zeiss 写在 TIFF 里；TESCAN 写在 TIFF 里或旁边的 `.hdr`；Hitachi 与 JEOL 写在同名 `.txt` 里。ImageJ / Fiji 保存的 TIFF（例如 FIB-SEM 图像序列）中的标定也会采用，并提示它不是仪器的原始记录。
2. **信息栏**：找到图片下方的信息栏，测出比例尺的像素长度，用文字识别读出它代表的长度。信息栏同时显示视场宽度（Thermo Fisher 的 HFW、Phenom 的 FW、Zeiss 的 Width）时，视场宽度 ÷ 图片宽度是同一像素尺寸的第二个独立读数：两者中**更精确的一个被采用**（视场宽度按印出的有效数字，比例尺按 1 像素的长度误差），两者相差超过合计误差的 3 倍（至少 1%）时提示核对；视场宽度与比例尺相差超过 20% 时视为读错，仍用比例尺。信息栏表格中各栏的数值（视场宽度、工作距离等）不会被误当作比例尺的标注。这种标定**要人确认后才算数**：核对后点顶部标定条上的“确认”（或“标定”页的“确认标定”）。
3. **手动**：“点比例尺两端…”后在图上依次点比例尺的两端，再输入它代表的长度（例如 500 nm）；或“输入像素尺寸…”直接给出（例如 2.5 nm）。

“标定”页还显示：比例尺的像素长度、各种来源之间的核对（相差超过 2% 时提醒，例如图片在采集后被缩放过）、分析区域（信息栏以上的行；信息栏不参与分析与测量）、仪器信息（厂商、加速电压、放大倍数、视场宽度、工作距离、样品台倾角、探测器、时间）。

找不到可靠来源时显示“未标定”和原因，不会给出猜测的数值；此时测量以像素为单位。经人确认的标定按文件的 SHA-256 记录，同一文件再次打开时直接使用。

文字识别是可选组件（RapidOCR 与 ONNX Runtime，完全在本机运行，不联网；见 2.3）。Intel 芯片的 Mac 不支持文字识别，只能用元数据或手动标定。

命令行：

```bash
uv run vexel sem info image.tif                   # 仪器元数据（厂商、像素尺寸、电压、放大倍数、倾角…）
uv run vexel sem calibrate *.tif                  # 每张图的像素尺寸、来源、核对结果、信息栏位置
uv run vexel sem calibrate image.tif --confirm    # 核对无误后，记录从信息栏识别的标定为“已确认”
uv run vexel sem calibrate image.tif --bar-length 500nm          # 手动：比例尺代表的长度（像素自动测）
uv run vexel sem calibrate image.tif --bar-length 500nm --bar-pixels 148   # 比例尺找不到时连同像素一起给
uv run vexel sem calibrate image.tif --pixel-size 2.5nm          # 手动：直接给像素尺寸
```

**准确度**（M1 验收）：合成图上五种厂商布局的信息栏识别与元数据相差 0.00%–0.19%；公开的 Thermo Fisher 与 Zeiss 样图相差 0.18%–0.98%。

**真实图片验收（第一轮）**：52 张 Phenom 样图（JPEG，信息栏数值由人逐张读出作为真值）：98% 的像素尺寸与“视场宽度 ÷ 图片宽度”相差在 1% 以内，其余 1 张相差 6.6%，已被视场宽度核对标出；全部 52 张都做了视场宽度核对；没有一张出错而未提示。3 个 ImageJ 保存的 FIB-SEM 序列标定准确。第二轮核对测量：去铁铁蛋白与 20S 蛋白酶体的粒径与文献值相差 +6.3% 与 −2.4%，轮状病毒与人工在图上量出的直径相差 0.1%。验收脚本：`tests/benchmarks/sem_real_eval.py --data <图片文件夹>`（图片不在仓库中）。

### 11.3 手动测量

在工具栏选工具，在图上操作；结果出现在“测量”页的表格里（编号、工具、结果、名称）。

| 工具 | 操作 | 结果 |
| :--- | :--- | :--- |
| 长度（L） | 点两点 | 长度、水平与垂直分量、与水平方向的角度 |
| 折线（Shift+L） | 逐点点击，双击或回车结束 | 总长度 |
| 面积（A）/ 自由画（F） | 逐点点击后回车闭合 / 按住沿轮廓画 | 面积、周长、等效圆直径、中心 |
| 魔棒（W） | 点击区域内部 | 与点击处灰度相近的连通区域：面积（按像素计）、周长、等效直径；容差默认 50%，即边界在目标与背景灰度的中点 |
| 角度（G） | 一条边上的点、顶点、另一条边上的点 | 角度 |
| 计数（N） | 逐个点击目标，回车结束一组 | 个数；先在“计数类别”选择或输入类别（颗粒、缺陷、孔……） |
| 圆（C）/ 椭圆（E） | 在边上点 3 个以上 / 5 个以上的点，双击或回车拟合 | 直径（及拟合残差）/ 长短轴与方向 |
| 线剖面（P） | 点两点，横穿线条或台阶 | 灰度曲线、边缘位置、线宽、间隔、周期 |

- **修改**：选中一项后拖动小圆点；表格“名称”一栏可直接输入名称；Delete 删除；撤销与重做。
- **数值总是重新计算**：由所画的几何、当前标定和图像处理算出。标定或处理改了，所有结果随之更新。

**线剖面与线宽**：沿剖面线取灰度（垂直方向平均“剖面宽度”个像素以降噪），按选定的**边缘定义**找边缘：

- 阈值（默认 50%）：灰度穿过“低值与高值之间某一比例”的位置，常用于线宽（CD）；
- 最大梯度：边缘最陡处；
- 亮边峰值：SEM 台阶处的亮边，测两条亮边之间的距离。

**不同定义给出的线宽不同**，结果中总会写明所用定义和阈值；与其他设备比对时要用相同定义。选中线剖面时，“测量”页下方显示灰度曲线（绿线为上升边缘，红线为下降边缘）和线宽、间隔、周期。周期用剖面的自相关求出（不依赖边缘定义），也给出按同向边缘计算的周期。改“剖面宽度”“边缘定义”“阈值”会作用于选中的线剖面和之后画的线剖面。

**倾斜校正**：样品台倾斜 θ 时，垂直于倾转轴（图像垂直方向）的距离被缩短为 cos θ。勾选“倾斜校正”后，垂直方向的距离除以 cos θ（倾角默认取自元数据）。只对平整样品成立。

命令行：

```bash
uv run vexel sem measure image.tif                         # 这张图已保存的测量：重新计算并列表
uv run vexel sem measure image.tif -o m.xlsx -o m.png      # 导出 Excel 与标注图（也可 .csv .svg .json）
uv run vexel sem measure image.tif --record m.json --tilt 52   # 用指定的测量记录、倾斜校正 52°
uv run vexel sem profile image.tif --from 10,240 --to 790,240 --width 9 --method threshold --level 0.5
```

`vexel sem profile` 适合在脚本中批量测线宽与周期（`--json` 输出全部边缘位置）。

**准确度**（合成数据，真值已知）：长度、面积、角度与所画几何精确一致；圆与椭圆拟合（点击偏差半个像素）直径误差 ≤ 1 像素；魔棒等效直径误差 ≤ 1 像素（直径 12 像素以上）；线剖面线宽误差 ≤ 0.5 像素、周期误差 ≤ 0.2 像素（阈值与最大梯度两种定义）。

### 11.4 图像处理

“图像处理”页（视图 → 图像处理）：从下拉框选一个步骤，点“添加”；选中步骤后在下方调参数；勾选框可暂时关闭它；“上移”“下移”调整顺序；“删除”去掉。处理只作用于信息栏以上的部分。

| 步骤 | 作用 | 注意 |
| :--- | :--- | :--- |
| 逐行校平 | 让每条扫描线的亮度（中位数）与相邻扫描线一致，去掉沿扫描方向的明暗条纹 | 默认也会压平上下方向的缓慢亮度变化；需要保留时把“保留宽于”设为几十行（条纹去得会少一些）。会压平与扫描方向平行的真实结构 |
| 傅里叶去条纹 | 条纹沿行有强有弱时用：在频谱中压低条纹方向的成分 | 与条纹同方向的真实结构也会被削弱；“频带宽度”越大去得越多，也越伤结构 |
| 背景校平 | 估计大范围的亮度不均（一侧亮、中央亮）并扣除或相除：多项式曲面、高斯、滚球 | 滚球保留比球小的亮特征；“相除”适合探测器收集不均 |
| 行错位校正 | 把水平错开的扫描线对齐（与上下相邻行比较，亚像素） | 只能对齐有水平方向细节的行；没有细节的行保持原样 |
| 去噪 | 非局部均值（推荐，保边）、中值、双边、高斯 | 高斯会把边缘抹宽，测线宽前慎用；测线边缘粗糙度前不要去噪 |
| 对比度（仅显示） | 黑点、白点、伽马、局部直方图均衡（CLAHE） | 只改变显示和导出的图 |
| 锐化（仅显示） | 反锐化掩模 | 边缘有过冲，只用于展示 |

- **校正步骤的结果用于测量**（魔棒、线剖面、自动测量都在校正后的图上计算）；“仅显示”的步骤不影响任何数值，并且总在校正步骤之后运行。
- 较慢的步骤（非局部均值、双边、滚球）在后台计算，期间窗口可以继续使用；完成后数值和图像自动更新。
- 处理步骤保存在这张图的记录里，随测量一起撤销、重做和恢复；导出的 Excel 有“图像处理”一页。
- **饱和区**：严重荷电或探测器饱和处的信息已经丢失，Vexel 只**标记**，不“修复”；默认不画在图上，右侧顶部提示有饱和区，点“在图上显示”或勾选本页的“在图上显示（红色）”才画出红色。阈值自动取探测器上限（8 位 255、16 位 65535，或图中最亮值形成的平台，例如 12 位探测器的 4095），并向外扩 1 个像素。魔棒不把饱和像素算进区域，点在饱和区上会拒绝；线剖面不取饱和区内的边缘，也不计算跨越它的线宽、间隔和自相关周期，并在结果中注明。可以关闭标记，或只隐藏红色显示。
- **前后对比**：勾选“左侧显示原图”，拖动滑块移动分界线。
- **多帧平均**：同一位置拍了多帧时，打开第一帧，点“多帧平均…”选其余帧。各帧先按亚像素对齐（漂移）再平均，结果存为新的 32 位 TIFF，沿用第一帧的标定并自动打开；状态栏显示噪声下降与最大漂移。
- **导出处理后的图**：校正后的图（32 位浮点 TIFF，信息栏保留），在 Vexel 中打开时沿用原图标定。

荷电最有效的办法在采集端（降低加速电压、缩短驻留时间、交错扫描、镀膜）；软件处理只是补救。

命令行：

```bash
uv run vexel sem process --list                                   # 全部步骤与参数
uv run vexel sem process image.tif -s line_level -s denoise:method=nlm,strength=1.2 -o fixed.tif --picture fixed.png
uv run vexel sem process image.tif -s background:method=rolling_ball,size=80 --save   # 存进这张图的记录，窗口和 sem measure 随之使用
uv run vexel sem average f1.tif f2.tif f3.tif -o avg.tif           # 对齐后平均
```

**处理效果**（合成图注入伪影，处理后误差 / 处理前误差）：行条纹 ≤ 0.03；沿行渐变的条纹 0.21–0.32；亮度不均 0.06–0.12；噪声 0.27（非局部均值）；行错位 0.26（线条图案）；全部叠加 0.16–0.23。饱和像素 100% 标记，干净图零误报。四帧平均对齐误差 ≤ 0.09 像素。线条图案经条纹、亮度不均与噪声后，线宽误差从 0.31 像素降到 0.05 像素。

### 11.5 自动测量

“自动测量”页：选方法 → 点“框选区域”在图上点两个对角（不框选则用整张图，信息栏以上）→ 调设置 → “运行”。

每次运行成为一项自动测量（A1、A2……），和手动测量一起保存在这张图的记录里，可撤销、可导出；改了标定或图像处理，结果自动重算。选中一项可看汇总、每个对象的数值（每条线、每个孔、每个颗粒……）和警告；“在图上显示”可以暂时隐藏自动测量的轮廓，方便手动测量。

**设置**：每种方法的全部设置收在“高级设置”里，一般不用改（默认值适合大多数图像，自动规划也会替你选）。展开后：

- 改过的设置以蓝色“●”标出，鼠标停在名称上显示默认值；“高级设置”后面写着改了几项。“恢复默认设置”一键还原。
- **选中一项自动测量时**，面板显示它的方法和设置；改动设置后约半秒自动重算它，图和数值随之更新（每次改动都可撤销）。不选中时，设置用于下一次“运行”。
- “用当前设置重算所选”把新框选的区域用到所选测量上。

**点选纠错**（颗粒与缺陷、孔隙、接触孔）：结果不对时，不必调参数，在图上指出就行。

1. 选中这项自动测量，点 **点选纠错**。
2. 在图上点例子：**左键**点应该测到的对象（绿圈），**右键**或 **Shift+左键**点不该测到的（红叉），例如被误当作颗粒的噪点或碎屑。几个就够。
3. 点 **按例子调整**。Vexel 用同一种方法、换不同的设置（亮暗、阈值方式、平滑、分开相连、最小直径）各重测一遍，按“符合几个例子”排序，相同时优先结果中对象大小与你点的例子相近、改动少的；并排显示最好的三个（缩略图、符合的例子数、对象数、主要数值、改了哪些设置）。
4. 点 **用这个** 采用其中一个（可撤销）。改动写进这项测量的设置，和手动调参的结果一样可复现。

**方案**：一项满意的自动测量可以 **存为方案…**（例如“M1 线宽”），连同本图的图像处理一起保存。以后在别的图上选这个方案点 **应用方案**，一步得到同样的测量；勾选 **打开图片时自动套用这个方案**，还没有测量的图片一打开就按它测量（不再自动规划）。方案保存在 `~/.vexel/sem/methods.json`。

**批量测量…**：用所选方案测量一批图片，每张用自己的标定，不改动各图的记录。结果按“需要看”排在前面：出错、未标定或标定待确认、有提示、主要数值与这批的中位数相差超过 3.5 个稳健标准差；勾选“只显示需要看的”时正常的不显示。双击一行打开那张图，可以导出 Excel。

**看不出结构的区域**：空白、失焦或噪声过大的图像（灰度差不到噪声的 1.5 倍）不会给出数值，而是提示“区域内看不出结构”。

| 方法 | 框选什么 | 结果 |
| :--- | :--- | :--- |
| 线条与间隔（CD、LER/LWR） | 一组完整的线条（两侧边缘都在框内），沿线方向尽量长（几百行） | 线宽 CD、线间差异、间隔、周期（线中心与自相关两种）、线边缘粗糙度 LER 与线宽粗糙度 LWR（3σ，含噪声与扣除噪声两种）、噪声造成的边缘抖动、相关长度、采样行数与间距、线条倾斜；每条线的数值 |
| 接触孔与通孔 | 孔阵列或单个孔 | 孔径（圆拟合）、等效直径、椭圆长短轴与方向、圆度、孔径均匀性 3σ、阵列周期与夹角、缺失的孔（图上红圈）、疑似相连的孔 |
| 颗粒与缺陷 | 颗粒所在区域 | 等效圆直径、Feret 最大/最小直径、圆度、长宽比、凸度与凸包周长比、平均灰度、粒度分布 d10/d50/d90（数量与体积加权）、相互接触的比例、面积分数；每个颗粒的分类（正常、团聚、不规则、异常） |
| 孔隙 | 多孔材料、膜的表面或截面 | 孔隙率（孔所占面积比例）、孔数、等效圆直径与分布 d10/d50/d90、每个孔的 Feret 直径、圆度、长宽比 |
| 纤维 | 纤维网（无纺布、静电纺、熔喷、膜） | 纤维直径（平均、标准差、中位数、d10/d90、最小/最大，按长度统计）、主方向与取向度、纤维覆盖率、纤维间缝隙的大小；每段纤维的直径、长度与方向 |
| 截面层厚 | 层叠的截面：水平、倾斜、弯曲或竖直 | 每个界面的位置与粗糙度、每层厚度及其均匀性（逐列测量）；倾斜或弯曲的层先拉平，厚度沿局部法向，并给出层面弯曲 |
| 截面轮廓（侧壁角） | 一个线条或沟槽的截面，四周留出背景 | 高度（深度）、顶/中/底宽度（10%、50%、90% 高度处）、两侧侧壁角 |
| 尖端 | 一个尖端 | 曲率半径及其不确定度、锥角（两侧半角）、轴向、可见长度 |
| 导线与焊盘（PCB、芯片金属层，预览） | 俯视的导体：电路板的铜走线与焊盘、芯片上的金属线 | 走线宽度（沿中心线，按长度平均）、最窄走线、圆形焊盘直径、不同导体之间的最小间距及位置、导体覆盖率；不是圆形的宽区域（方焊盘、锐角拐弯）单独列出 |
| 嵌套区域（细胞核/细胞，预览） | 细胞（组织切片或玻片上的细胞），或其他“区域里套着子区域”的对象 | 每个完整区域的面积与其中子区域（细胞核）的面积、子区域/区域面积比、核质比 N/C（子区域/其余部分）；没有子区域的区域写明原因 |

- **线条方向**自动判断（竖直或水平）；略有倾斜时自动扣除，线宽按垂直于线的方向计。
- **边缘定义**（阈值、最大梯度、亮边峰值）不同，线宽和孔径也不同：结果里总写明所用定义；与 CD-SEM 比对时要用相同定义。亮边峰值在线条本体比间隔亮时会落在线内一点（合成数据上线宽约窄 0.9 像素）；孔边有亮环时，阈值与最大梯度两种定义相差约 0.3 像素。
- **粗糙度**：边缘位置相对拟合直线的标准差，报 3σ。图像噪声会让边缘抖动、使粗糙度偏大；Vexel 用边缘位置功率谱中的白噪声底（粗糙度模型加常数拟合）把它扣除，同时给出扣除前的值和噪声大小。粗糙度没有统一的官方算法，只有在相同边缘定义、采样与噪声处理下才能相互比较；电子束的模糊本身会让可见的粗糙度偏小，这属于仪器分辨率，不做校正。区域少于 64 行时给出警告。
- **预览中的测量**：嵌套区域、导线与焊盘还没有在真实图像上验收，0.8 中只在设置 `VEXEL_PREVIEW=1` 时出现在方法列表里；含有它们的旧记录照常打开和重算。线宽、接触孔、层厚、侧壁角、尖端、孔隙、纤维只在合成图像上验收过，结果下方会注明，请与现有测量对照后再使用。
- **导线与焊盘**：相连的导体算一个网络。走线宽度在中心线上逐点横向量取（与纤维直径同一方法），避开焊盘、交叉、端点与边界；“最窄走线”取各走线段宽度中位数的最小值（单点有噪声），在焊盘之间只有一两个线宽长的走线测不到宽度，警告会写明有几个导体没测到。焊盘是比同一导体走线宽得多的部分，直径为边缘点的拟合圆；方焊盘、锐角拐弯和交叉处的宽区域不是圆形，单独列出、不计入焊盘统计。间距是两个相邻导体在阈值处轮廓之间的最短距离，图上用红线标出最小间距（S min）与最窄走线位置（W min）。合成电路板上：走线宽度偏差约 0.01 像素、单段最大 0.4 像素，圆形焊盘直径与最小间距误差不超过 0.4 像素（线宽 3–30 像素、模糊 1–1.5 像素）。限制：图像模糊会把方焊盘的尖角磨圆，所以到尖角的间距读大，模糊 1 像素时约大 1 像素；圆形边缘之间的间距也略大（约 0.1–0.3 像素）。没有设计图可比，所以不判断开路与短路：相碰的两条走线算一个网络，断开的走线算两个。彩色照片按灰度（三个通道的平均）处理，铜要比阻焊层亮。
- **嵌套区域**：“区域是”可选三种：由暗膜线围成（组织里相邻细胞共用一条膜，按膜线中央分开；玻片上带暗色轮廓的细胞）、比背景暗或比背景亮的对象（边缘取在对象与背景的半对比度处）。“膜线宽度”填膜线大致的像素宽度；“区域最小直径”请设为细胞的大致直径。子区域在每个区域内部、离开膜线处，按区域内两种灰度的中点分出，取最大的一块（可改为多块）并填补空洞；区域内部灰度差不到噪声的 2 倍时认为没有子区域。被区域边界截断的区域不计，单独计数。合成数据上：组织中细胞面积误差约 0.1%、细胞核面积约 0.5%、面积比约 0.2 个百分点；明亮玻片上带膜细胞的面积偏小约 1%（边界略向细胞内偏）；无膜的暗对象约 0.5%。限制：找到的区域大多只有最小直径左右时，判为纹理碎片并拒绝测量（电镜切片中细胞内部纹理很强，膜线可能无法与纹理区分）；尺度约 20–30 像素的随机纹理仍可能被当作细胞，请看图核对轮廓。
- **截面层厚**：“层面形状”默认自动——层面跨区域移动 1 像素以上时，先逐列对齐把层叠拉平（共形沉积膜在弯曲处沿法向等厚，拉平按深度分段进行），再沿每列的局部法向量厚度（竖直厚度 × 层面局部斜率的余弦）；层面水平时与以前完全相同（竖直量）。“层的走向”可选竖直或自动。合成数据上，倾斜 6°–12°、弯曲 30–60 像素的三层膜厚度误差 ≤ 0.19 像素（竖直量会偏大 1.3–2.9 像素或丢失界面）；40 层 6/8 像素交替的弯曲细层（类似 3D NAND 字线堆叠）全部找到，平均误差约 0.2 像素——这主要来自最大梯度边缘定义在相距仅几像素的模糊边缘之间的偏移（水平细层同样存在），阈值定义可作对照。拉平假定各层共形；非共形的界面靠逐列跟踪跟随。
- **侧壁角**在特征内部、底部量：90° 为垂直；小于 90° 表示底部比顶部宽。FIB 截面在 52° 样品台倾角下拍摄时，垂直方向被缩短为 sin 52°：在“测量”页勾选倾斜校正并填 38°（1/cos 38° = 1/sin 52°），高度和侧壁角随之校正。
- **颗粒**：按 ISO 13322-1，被区域边界截断的颗粒不计入统计（单独计数）；颗粒小于 10 像素时给出警告。平滑会让小颗粒的轮廓向内收，颗粒小于 15 像素时平滑不要超过 0.5 像素。
- **颗粒分类**是可以核对的规则，不是训练出的模型，图上按类别着色，表中“reason”列写明依据：**团聚**＝与其他颗粒相连（被分水岭分开的同一团）；**不规则（可能破碎）**＝凸度（面积 / 凸包面积）低于设定值（默认 0.85），破碎、有棱角或粘连的颗粒较低；**异常（可能是异物）**＝尺寸（取对数）或平均灰度偏离总体超过设定的稳健标准差倍数（默认 4），至少 8 个颗粒时才判断；其余为**正常**。一个圆颗粒因轮廓噪声被分成两半时会自动合并回去。
- **孔隙**：孔隙率按孔相（默认暗相）占区域的比例计算，被区域边界截断的孔也计入；孔径统计只用完整的孔。孔隙率超过 60% 时提示检查亮暗设置或阴影。
- **纤维**：先分割纤维、求中心线，在每个中心线像素处沿垂直方向读灰度剖面，两侧边缘之间的距离就是直径（做法与 NIST 的 DiameterJ 相同，但边缘到 1/4 像素）。交叉点、纤维端点和区域边界附近不测。默认的边缘定义是“最大梯度”：二次电子在纤维边缘增亮，按阈值会把直径量大（8–12 像素的纤维约大 7%），最大梯度受影响小得多。直径按长度统计（每个测量点约代表 1 像素长的纤维）。**取向度**为 0 表示方向完全随机，1 表示全部平行；主方向从水平方向逆时针计 0–180°。像素不是正方形（倾斜校正）时按真实的垂直方向换算直径。
- **分布图**：选中一项颗粒、孔、孔隙或纤维测量，表格下方显示分布图：选择横轴的量（纵轴选“直方图”或另一个量画散点图），线性、对数或双对数坐标，直方图可按数量或按体积（直径³ 加权）。
- **多张图合并统计**：一张图里的对象太少时，点“多张图合并统计…”选其他图片：用所选测量的方法、设置、区域和本图的图像处理测量它们（每张图用自己的标定，未标定的不计入），把全部对象合在一起给出平均、标准差、d10/d50/d90 和分布图，可保存为 Excel。
- **尖端**：拟合范围对半径影响很大。Vexel 取拟合残差突增（开始包含锥面）之前的最大范围，并把相邻范围的变化作为不确定度；半径小于 10 像素时误差可能超过 5%，结果会提示。
- 饱和区（11.4）中的像素不参与：经过饱和区的边缘记为缺失，接触饱和区的孔跳过。

**重复性**：半导体计量看重同一位置重复拍摄时结果的分散程度。把同一位置的多张图放在同一个文件夹，用命令行一起测量，输出每个结果在这组图上的平均、标准差与 3σ：

```bash
uv run vexel sem analyze --list                                         # 全部方法与设置
uv run vexel sem analyze spot1/*.tif -r lines -o cd.xlsx                 # 每张图一行；按文件夹给出重复性（3σ）
uv run vexel sem analyze image.tif -r holes --region 20,20,780,580 -p method=gradient --save   # 存进记录，窗口中可见
uv run vexel sem analyze image.tif -r tip -p cone_from=40 -p cone_to=200
uv run vexel sem analyze lots/*/*.tif                                    # 用各图记录里已保存的自动测量
```

Excel 输出有四页：结果（每张图每项测量一行）、重复性（按文件夹分组）、合并统计（颗粒、孔、孔隙、纤维：同一文件夹所有图的对象合在一起）、对象（每条线、每个孔、每个颗粒……）。

```bash
uv run vexel sem analyze batch3/*.tif -r particles -o particles.xlsx    # 每张图的结果 + 全部颗粒合并后的粒度分布
uv run vexel sem analyze mat/*.tif -r fibres -p method=threshold        # 纤维；边缘定义改为阈值
uv run vexel sem analyze membrane.tif -r pores --region 0,0,1024,880    # 孔隙率
```

**准确度**（合成数据，几何真值已知）：线宽误差 ≤ 0.013 像素（含 2.9° 倾斜、暗线条、强噪声；荷电条纹下线宽变化 0.013 像素）、周期 ≤ 0.01 像素；扣除噪声后的 LER 与真实边缘相差 ≤ 2%（噪声强到未扣除时偏大 44% 也一样），LER/LWR 与无噪声图相差 1.1–2.2%（相关长度 3–25 行）；孔径（无亮环）偏小 0.15–0.40 像素（小孔更明显）、中心 ≤ 0.13 像素，缺失的孔全部找到；颗粒直径中位误差 0.4–1.7%（直径 12–24 像素，含 20% 相互接触），d50 误差 ≤ 1.6%；层厚 ≤ 0.25 像素；侧壁角 ≤ 0.02°，宽度 ≤ 0.3 像素；尖端半径 ≤ 3.7%（半径 8 像素）、≤ 3.1%（20–40 像素），锥角 ≤ 0.1°。同一图案十次重拍（噪声不同）：线宽 3σ 0.013 像素，平均孔径 3σ 0.03 像素。纤维直径（含弯曲纤维与交叉）：边缘清晰时偏差 ≤ 0.3%（8–40 像素）、4–6 像素时 ≤ 1.5%；有边缘增亮时偏大 5%（8–12 像素）、2.7%（16–24 像素）、1.4%（30–40 像素），约为半个像素；平行纤维的取向度 ≥ 0.99、主方向误差 ≤ 0.6°；孔隙率误差 ≤ 0.001；颗粒分类在 5 张测试图上全部正确。

### 11.6 自动规划

**打开即规划**：勾选“打开图片时自动规划”（默认勾选）后，打开一张还没有自动测量的图片时 Vexel 立即做下面的事，不需要点任何按钮。也可以在“目标”里用中文或英文写想测什么（例如“线宽和粗糙度”“孔径”“膜厚”“沟槽侧壁角”“针尖曲率半径”“孔隙率”“纤维直径”），按回车或点“自动规划”。Vexel 会：

1. 识别图像拍的是什么：线条与间隔、接触孔阵列、颗粒/缺陷、截面层叠、截面轮廓（单个线条或沟槽）、尖端，或者“其他”。没有把握时显示“无法确定”和候选类型，不猜。
2. 选择测量方法和设置（哪种灰度是目标、边缘定义、区域、需要的图像处理），每一项都写明理由。
3. 在这张图上试运行并检查结果（例如线条够不够、各线线宽是否一致、孔是否圆、曲率半径是否随拟合范围变化）；不通过时自动尝试其他设置，保留最好的一次。
4. 把试运行的结果画在图上，并在**结果卡**上显示：识别出的图像类型和测量方法、关键数值（例如颗粒数、平均直径）、检查结果（✓ 通过，! 提示，✗ 问题）和前三条理由（“全部理由”展开其余）。由你选择：
   - **采用**：加入这张图的记录（可撤销）；以后在相似的图像上会参考这次被采用的设置。
   - **调整**：把方法、设置和区域填到下方面板并展开“高级设置”，改好后点“运行”。
   - **我自己来**：不用这个规划，在下方手动选择方法。

规划在后台进行，期间窗口可以继续使用。卡片右上角的状态：“试运行通过”表示通过全部检查；“通过，有提示”请核对提示；“需要你来决定”表示图像类型不明确或没有得到可用结果，请在下方手动选择方法。已有自动测量、手动测量或三维设置的图片打开时不再自动规划。

需要注意的约定与限度：

- **线条与间隔**：较窄的条纹按“线条”计（接近 1:1 时取亮条）。如果贵司的约定相反，把设置中的“线条是”改过来。
- 测线边缘粗糙度时不会建议去噪（去噪改变边缘起伏）；图中结构是水平的时不会建议逐行校平（会压平真实结构）。
- 识别规则在合成图像上验证（正确率 97–99%，没有出现有把握地认错），在真实图片上的表现要在最终验收时确认。
- 孔隙和纤维的图像还不能自动识别：在“目标”里写“孔隙率”或“纤维直径”（或手动选择方法），规划会选对方法并试运行。

如果配置了语言模型（液滴窗口的 帮助 → 规划模型设置）且组织策略允许，模型可以参与选择方法和调整设置：它只能从各方法的参数清单中、在范围内提出建议，每条建议都经检查和试运行，最后由你确认；默认只发数值，不发图片。组织策略禁止联网时只用离线规则。

命令行与助手：

```bash
uv run vexel sem plan image.tif --goal 线宽                 # 识别与规划（含试运行），显示理由；不改动记录
uv run vexel sem plan lot/*.tif --offline --apply          # 只用离线规则，把可用的规划加入各图记录
uv run vexel sem analyze lot/*.tif --auto -o results.xlsx  # 没有自动测量的图先规划再测量；多张图给出重复性
```

`vexel mcp` 提供 `sem_calibrate`、`sem_plan`、`sem_analyze`：Claude 等助手可以按“标定 → 规划（给你看理由）→ 你同意后测量”的顺序操作；数值都来自 Vexel 的测量方法，助手不自行估计。

### 11.7 倾转三维（2.5D 高度图）

> 0.8 版中倾转三维移到下一阶段：“三维”页默认隐藏，设置环境变量 `VEXEL_PREVIEW=1` 后出现；已经含有倾转图的测量记录打开时仍会显示。命令行 `vexel sem tilt3d` 不变。

同一位置在不同样品台倾角下各拍一张（例如 −5° 与 +5°，或 0°、5°、10°）。打开其中一张作为参考图（高度图画在它上面），在“三维”页点“添加倾转图…”选其余的图，核对表中的倾角（有元数据时自动填入，没有时手动填写），点“重建高度图”。重建在后台进行，每对图几秒钟。

- **倾角**：建议倾角差 10°–15°。高度由视差算出，视差噪声被放大 cos φ / sin Δφ 倍（10° 时约 5.7 倍），倾角差越小高度越不准，小于 3° 时会提示。参考图最好是倾角范围一端的那张。
- **倾转轴方向**：倾转轴在图像中的方向，通常是水平（0°）；扫描旋转过时按实际方向填写。沿轴方向有明显错位时会提示方向可能设错。
- **置信度**：每个像素都有匹配置信度。平坦、无纹理的区域没有可匹配的细节（文献报道这种区域误差可达 46%），会标为不可靠（低于“最低置信度”），在高度图上以灰色显示，不参与粗糙度和台阶高度。
- **显示**：原图、彩色高度图（深蓝低、黄色高）、置信度；“三维预览…”可旋转、可放大高度，仅供观察，不用于测量。
- **校平**：扣除平面（默认）或二次曲面，用于去掉样品整体倾斜和非共心倾转带来的整体倾斜。
- **粗糙度**：ISO 25178 的 Sa、Sq、Sz（及 Sp、Sv）、Ssk、Sku，按校平后的可靠像素计算。
- **高度剖面**：点“画高度剖面”，在图上点两点，下方显示高度曲线，并给出剖面粗糙度（ISO 21920：Ra、Rq、Rz、Rp、Rv、Rt、Rsk、Rku）。先扣除最小二乘直线，再用 ISO 16610-21 高斯滤波去掉比截止波长 **λc** 长的起伏（波纹度）；λc 在设置中填写，默认取剖面长度的 1/5（即五个取样长度）。Rz 为各取样长度内峰谷高度的平均；剖面不到五个 λc 长时按实际段数计算并提示。不可靠的像素用两侧插值。
- **台阶高度**：点“测台阶高度”，先框选下平面，再框选上平面。按 ISO 5436-1 用两个平行平面拟合，不受样品整体倾斜影响；结果附不确定度（含高度图本身的不确定度）。
- 改了倾角、图像或重建设置后，结果会注明“已改变”，点“重建高度图”更新。“清除三维”去掉这张图的三维设置。
- 重建所用的图（文件名与 SHA-256）、倾角和设置保存在参考图的记录中，重新打开后点“重建高度图”即可复现；所用的图被改动过会提示。

命令行：

```bash
uv run vexel sem tilt3d ref.tif tilt10.tif --tilts=0,10 -o height.tif --mesh height.stl --picture height.png
uv run vexel sem tilt3d a.tif b.tif c.tif --tilts=-5,0,5 --step 10,20,80,300,300,20,370,300 --profile 10,160,370,160 --json
```

第一个倾角是负数时写成 `--tilts=-5,0,5`（带等号）。文件元数据中有倾角时可以省略 `--tilts`。剖面粗糙度的截止波长用 `--cutoff`（nm），例如 `--profile 10,160,370,160 --cutoff 200`。

**准确度**（合成数据，已知高度）：±5° 倾角、正常噪声下高度误差为起伏的 2.8%–4.4%（约 1–1.5 像素，与起伏大小无关；起伏小于约 25 像素时相对误差超过 5%）；台阶高度误差 ≤ 4.9%，且在报告的不确定度 2 倍以内；倾转轴竖直同样适用。

### 11.11 Web 工作台与 Python 引擎

> Web 工作台自 2026-11-28 起冻结（0.8 计划：桌面版是唯一的产品界面），本节只供开发者参考。

`web/` 里的 Web 工作台（浏览器界面）可以把当前图片交给本机的 Python 引擎测量：浏览器里的数字只是预览，Python 引擎的结果经过合成与真实图片验收，以它为准。图片只在本机之间传递。

1. 启动 Python 引擎（本机 127.0.0.1:8765）：

   ```bash
   uv run --extra web --extra sem vexel serve
   ```

2. 启动 Web 工作台（需要 Node.js 22）：

   ```bash
   npm --prefix web ci
   npm --prefix web run dev
   ```

   浏览器打开 http://localhost:3000 ，在右上角的引擎设置里选“本地 Python 引擎”，点“测试连接”。
3. 在“结果”页，SEM 线条、接触孔、颗粒、纤维、多层截面、弯曲多层、层级嵌套（细胞核/细胞）与 PCB 板检测工作流的最上方是“Python 引擎（已验证）”卡片：点“用 Python 引擎测量”。卡片写明引擎版本、所用方法与标定、警告；浏览器预览与 Python 测同一个量（线宽 CD、孔径、颗粒 d50、纤维直径、多层总厚、平均核/细胞面积比、平均走线宽度）时给出两者相差多少，超过 2% 时标黄；两边找到的对象个数不同时（孔、颗粒、层、细胞、焊盘）另行提示，此时数值差异不能说明一致与否。

注意：

- **上传的图片交给 Python 的是原始文件本身**（TIFF、PNG、JPEG、BMP）：Web 工作台为了显示把图缩到最长边 960 像素、转成 8 位，Python 则按原始分辨率和位深测量，并自己读取文件里的仪器元数据与信息栏。卡片写明测的是“原始文件”还是“工作台显示的像素”；内置示例和 Gatan DM3/DM4 交的是显示的像素，Python 读不了的文件会说明原因并改测显示的像素。你确认过的信息栏裁切会一并交给 Python（底部信息栏：只测其上方；顶部信息栏：只测其下方的区域）；没有裁切时，Python 自己找信息栏。
- **Python 的测量轮廓画在图上**（虚线，颜色与 SEM 窗口相同：颗粒按分类着色，层界面、线条边缘、细胞与细胞核的轮廓、黄色虚线框为测量区域），按原始文件与显示图像的比例和裁切换算到画布上，可在卡片上关闭。它们只对测量时的那张图（同一裁切）和那个工作流显示。
- **只有测得的标定才交给 Python**：仪器元数据、你在比例尺上手动描出的标定、或你确认过读数的信息栏。Web 工作台给上传图片的默认值（没有比例尺的 SEM 图默认 2 nm/px）不是标定，此时 Python 以像素给出长度，并说明原因。
- 工作流与图像不符时（例如内置的俯视线条示例用多层截面工作流），卡片上方有提示；上传的图片只按大类（SEM、细胞、液滴、PCB）判断，因为它在 SEM 内的具体类型是按文件名猜的。
- 其他工作流（叠加颗粒、三维体分析等）还没有经过验收的 Python 计量，卡片会说明下方数字仅为预览。
- 内置的肾切片示例是透射电镜图：两个圆形对象是细胞核（核膜），其中的暗团是核仁，所以浏览器给出的比值是核仁/细胞核；这张图的纹理很强，Python 会拒绝测量并说明原因。
- 多层截面：浏览器的“弯曲多层”方法在合成的倾斜、弯曲层叠上层数与厚度都不对（见 `tests/benchmarks/web_layer_parity.py`），请以 Python 结果为准。

接口（给开发者）：`GET /api/v1/sem/recipes?lang=zh|en` 列出全部 SEM 测量及其设置；`POST /api/v1/sem/measure` 测一张图（灰度像素或原始文件、可选的像素尺寸、设置），返回数值、单位、标定、警告与轮廓（坐标为所交图像的像素；交原始文件时可用 `crop_rows` 或 `region` 限定测量范围）。

包里有软件与依赖版本、操作系统、规划模型设置（只记是否设置了密钥，不记密钥本身）、每个结果文件夹的 `provenance.json`、`recipe.json`、`summary.json`、方案与修改记录、可疑液滴表、在线报警。**不含图像、视频、报告和密钥**；绝对路径只保留文件名（`--keep-paths` 保留全路径）。加 `--tables` 才附上逐个液滴的表格。

**模块**：

```bash
uv run vexel modules                  # 列出模块
uv run vexel modules my_file.tif      # 这个文件属于哪个模块（各模块的打分）
```

**组织策略**（数据不能出网的单位，由 IT 管理员设置）：

```bash
uv run vexel policy                   # 当前生效的策略，以及实际可用的规划模型
```

管理员把一个 JSON 文件放在普通用户不能修改的系统位置：

- Windows：`%PROGRAMDATA%\Vexel\policy.json`
- macOS：`/Library/Application Support/Vexel/policy.json`
- Linux：`/etc/vexel/policy.json`

也可以用环境变量 `VEXEL_POLICY` 指向文件。内容例如：

```json
{"offline": true, "allowed_hosts": ["llm.intranet.example"], "allow_images": false, "note": "工厂规定 FP-12：禁止外网访问"}
```

- `offline` 为 true 时，Vexel 不向外发送任何请求，自动规划只用离线规则引擎。例外是 `allowed_hosts` 中列出的内部服务，例如本机的 Ollama（`localhost`）或公司内部的模型网关。
- `allow_images` 为 false 时，任何情况下都不发送诊断图。
- 用户自己的设置只能更严格，不能放宽策略。策略文件存在但无法读取，或 `VEXEL_POLICY` 指向的文件不存在时，按最严格的设置执行：禁止一切网络请求。
- 规划模型设置窗口顶部会显示策略内容，被禁止的选项不可选。诊断包里记录当前策略。
- Vexel 除规划模型外不发出任何网络请求，没有使用统计或自动更新。因此这项策略覆盖了它会发出的全部数据。

**依赖许可证清单**（`CHECK` 标记 GPL 或非商用条款，`UNKNOWN` 表示包未声明）：

```bash
uv run vexel licenses
```

**命令返回码：**

| 返回码 | 含义 |
| :--- | :--- |
| 0 | 成功 |
| 1 | `validate` 未通过 |
| 2 | 输入、配方或参数错误 |
| 3 | `run` 被质控规则中止 |
| 4 | `batch run` 有文件没有完成（失败、缺失或质控中止） |

## 13. 当前版本的限制

**微流控液滴模块**

- 桌面界面覆盖单个文件的分析、结果查看、画笔训练（3.7 节）、在线监控（3.8 节）、复核纠错（3.9 节）与批量分析（3.10 节）。
- 画笔分类器只区分“液滴”和“背景”两类；细胞的画笔训练、从人工修正中自动学习尚未实现。
- 自动规划只覆盖内置的液滴配方；语言模型只能在白名单内调整设置，不能设计新的处理流程。联网模型（Claude、DeepSeek、通义千问、Gemini）的规划效果尚未在有凭据的环境中测量。
- “新用户 15 分钟内完成一次分析”尚待真人测试（方案见 [新用户可用性测试](usability_test.md)）。
- 人工修正后总是整段重算，长视频可能要几分钟；轮廓修改只作用于单帧；3D 数据还不能修正。
- 桌面界面只能使用四个内置配方；自定义配方需用命令行。
- 只处理 2D 时序。可以同时读多个通道，但只分析一个 z 平面；3D 算子尚不执行。
- 内置配方假定液滴是圆的。长条形塞子、被挤压变形的液滴需要换用阈值加分水岭（见第 8 节）。液滴大小差别很大时需手动给出直径范围。
- 体积由 2D 投影直径和流道高度按理想几何换算，没有用液滴的三维形状测量校准过；浓度没有做稀释换算，也不含体积误差。
- 各通道分别存成不同文件的数据不支持，需要先合并成一个多通道文件。
- 荧光阴阳判读只有一个荧光通道；多色（如双色探针）判读尚未实现。
- 自动阴阳判读无法区分“全部阴性”和“全部阳性”；只有一群时一律按阴性处理并提示。
- 包裹计数要求细胞在液滴内部可分辨。紧贴液滴暗环的细胞会漏数；前后重叠的细胞会少数（真实数据上这是剩余错误的全部来源）。
- 真实数据只验证了两段录像（见第 10 节），且细胞数真值只有一人标注。荧光判读、体积换算尚未在真实数据上验证；路线图中的公开数据集下载与核对尚未接入。
- 视频按 RGB 三通道解码，灰度视频会多占内存。
- 每个处理块最多占用约 2 GB 内存（系统内存的 10%，上限 2 GB）。
- 只在 macOS（Apple Silicon）上人工使用过；Windows 与 Linux 只经过持续集成的自动测试和安装试运行。
- 分组统计只做单因素比较（一个 group 列）；多因素设计（如 条件 × 日期）、配对设计、剂量–反应拟合尚未提供。批量分析按文件依次进行，不在多台机器上并行。
- 点击式分割（SAM）、深度学习模型尚未提供；模型插件的接口已经确定（见 [设计说明](plugin_interface.md)）。

**SEM 模块（预览版）**

- 需要 `VEXEL_PREVIEW=1` 才能在界面中打开（命令行不受限）。全部功能只在合成图像和少量公开样图上验证过；真实图片（特别是 Hitachi、CD-SEM、截面图）的验收尚未完成。
- TESCAN、Hitachi、JEOL 的元数据字段取自公开的导入脚本，只在合成文件上验证；CD-SEM（如 Hitachi CG 系列）的文件格式尚未见到实物。
- Intel 芯片的 Mac 不支持文字识别（信息栏读数），只能用元数据或手动标定。
- 自动规划的识别规则基于合成数据。在真实图片上它不会认错（52 张样图中 0 张认错），但能认出的很少：有明确测量对象的 21 张里只认出 4 张，其余显示“需要你来决定”。写明目标（例如“颗粒”“孔隙率”“纤维直径”）或手动选择方法即可。用真实图片训练的分类器（M5 后半）尚未提供。深度学习分割尚未提供。
- 负染图像中密集的环状颗粒（例如包封蛋白）用颗粒测量分不出：颗粒是暗染色中的灰色圆环。背景中大量很小的染色颗粒会压倒数量统计；自动规划会提高最小直径（理由中写明），手动测量时请自己把“最小直径”设到真实颗粒的约 1/5。
- 纤维测量假设纤维比背景亮（或暗）且彼此可以分开；高度交织、大面积重叠或铺满视野的纤维网，缝隙统计没有意义。颗粒分类是规则，不能识别材料成分（没有能谱）；严重重叠的几个颗粒可能被当作一个，外形仍接近凸形时会被分为“正常”。
- 多张图拼接成大视野图、控制电镜采集（自动拍图、移动样品台）尚未提供。
- 倾转三维按平行投影、共心倾转处理；高度噪声约 1–1.5 像素（10° 倾角差），慢变的整体误差会影响相距很远的两处之间的台阶高度。
- SEM 的结果保存在每张图的测量记录里，不进入液滴模块的配方与批量分析；SEM 有自己的 HTML 报告（每张图一份），多张图的汇总、重复性与合并统计用 `vexel sem analyze` 或窗口中的“多张图合并统计”。
- 英文界面只覆盖 SEM 窗口。

内测期间的已知问题汇总在 [内测已知问题](closed_testing/known_issues.md)。

## 14. 常见问题

**`error: ... is not empty; choose another output directory or pass overwrite`**
输出目录已有内容。换一个 `-o`，或加 `--overwrite`。

**`error: no reader for ...`**
文件扩展名不在支持列表内（见 5.1）。

**`error: step 'seg': invalid parameters for ...`**
参数名或取值不对。用 `uv run vexel ops` 查看该算子的参数。

**`n_droplets` 为 0 或很少**
先看复核图。没有轮廓：分割没检出，按第 8 节调 `seg` 的参数。有轮廓：看 `summary.json`，`n_tracks_not_crossing` 很大说明轨迹没越过计数线，检查 `droplets.flow_axis` 和 `droplets.count_line`；`n_tracks_total` 远大于实际液滴数说明追踪断了，调 `track.max_distance_px`。

**`frequency` 明显不对**
检查帧间隔。`uv run vexel info` 显示的 `t=` 是否是真实的采集帧间隔（见 5.2 的注意事项）。

**结果单位是 px**
没有像素尺寸，见 5.3。

**`run` 提示 QC warning**
某项质控指标超出配方设定的范围。运行仍会完成，但结果需要对照复核图确认。

**大文件运行很慢才开始**
开始前的元数据读取是即时的；结束时的 `hashing input` 需要完整读一遍输入文件。可用 `--no-input-hash` 跳过。

**自动规划提示“跳过了 deepseek / qwen / gemini …”**
方案里写着跳过的原因：`API key not set` 表示没设置对应的环境变量（设置后要重新打开终端或 Vexel）；`HTTP 401/403` 是密钥无效或没开通；`HTTP 404` 多半是模型名已被服务商更改，在 帮助 → 规划模型设置 里改成当前的模型名；`not reachable` 是网络不通。无论哪种，规划都会改用离线规则引擎完成。

**界面打不开 / 启动报错**
在终端里运行 `uv run vexel gui`（或 `vexel gui`），把终端里的完整报错和 `uv run vexel bugreport -o 诊断包.zip` 生成的诊断包一起发给我们。

**模块选择窗口里 SEM 显示“开发中”，打不开**
SEM 是预览版，启动前设置 `VEXEL_PREVIEW=1`，见 2.3。

**SEM 图片显示“未标定”**
标定页写明了原因。常见的是：图片不是仪器保存的原始文件（截图、重新保存过），或 Hitachi、JEOL 的同名 `.txt` 没有一起复制。可以用“点比例尺两端…”或“输入像素尺寸…”手动标定，见 11.2。

**标定显示“待确认”**
来自信息栏文字识别的标定要人核对：对照图片上的比例尺，无误后点“确认标定”。

**信息栏的数字读不出来**
文字识别组件没有安装（见 2.3），或在 Intel 芯片的 Mac 上不可用。可以手动标定。

**测得的线宽与 CD-SEM 不一样**
先确认两边用的是同一种边缘定义（阈值的百分比、最大梯度、亮边峰值）和相同的平均方式：定义不同，线宽就不同，见 11.3、11.5。

**自动规划显示“需要你来决定”**
图像类型不明确，或试运行没有得到可用结果；理由里写明了原因。在“自动测量”页手动选择方法、框选区域后运行。

**高度图大片是灰色**
灰色是匹配置信度低的区域：表面缺少纹理，或两张图差别太大（倾角差过大、漂移）。试着用 10°–15° 的倾角差、清晰的图片，见 11.7。

**怎样报告问题**
填 [反馈表](closed_testing/feedback_template.md)，附上诊断包（第 12 节）；结果不对时，最好附上录像片段和你的参照值。
