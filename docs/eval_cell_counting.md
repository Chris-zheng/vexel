# 液滴内计数评估：是否需要“小模型”

日期：2026-11-14。目的：在内测数据回来之前，用手头的真实标注数据回答“包裹计数要不要换成训练出来的小模型”。复现：`uv run python tests/benchmarks/bead_counting_eval.py`。

## 一、数据

原计划用 Gardner 等的液滴细胞数据集（按每滴 0/1/2/3+ 个细胞标注，几千个液滴，正是训练小模型需要的数据）。但下载的 `droplet_detection-master.zip` 只有训练代码，**图像和标注在 Roboflow 和 Google Drive 上，需要登录账号下载**，许可证页面写的是“待核实”。所以这次用了手头能用的两套真实数据：

| 数据 | 内容 | 真值 | 许可证 |
| :--- | :--- | :--- | :--- |
| WSCNet2 示例序列（已有） | 300 帧明场，134 个液滴，每滴 0–3 个细胞 | 一人逐个液滴目测（见用户手册第 9 节） | 随 WSCNet2 代码（研究用途，待核实） |
| Droplet-Bead（Roboflow Universe, hrithikxoml/droplet-bead v1） | 一段流动聚焦视频的 35 帧，液滴里有 0–3 个珠子 | 液滴框与珠子框；珠子中心落在液滴框内即计入 | CC BY 4.0 |

Droplet-Bead 的几处情况会影响评估，需要先说明：

- 帧是从视频里**抽出**的，并被拉伸成 640×640。原画面为 16:9 加上下黑边，液滴被纵向拉长了 1.78 倍，评估前已还原。
- 抽出的帧里液滴几乎停在同一位置，等于“不流动”。
- 只有带亮心的环状珠子算珠子，液滴里更小的实心小点（杂质）没有标注。
- 35 帧是连续的，同一液滴会出现在几帧里，所以 103 个“液滴实例”并不相互独立。Roboflow 自带的 train/valid/test 划分按帧分，留出帧的估计偏乐观。

## 二、结果

**WSCNet2**（默认配方 `droplet_encapsulation`，开发时调过一次）：132 个确定的液滴中 122 个细胞数正确（**92%**），λ 1.49 对人工 1.57。10 个错误全部是两三个细胞前后重叠，看起来像一个。

**Droplet-Bead**：

| 设置 | 找到的液滴 / 标注 | 计数完全正确 | 留出帧上完全正确 | 差 ≤ 1 | 平均真值 | 平均计数 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全部默认 | 20 / 103 | – | – | – | 1.00 | 0.00 |
| 给出液滴直径范围，关闭运动门控 | 96 / 103 | 3% | 3% | 14% | 0.82 | 5.07 |
| 再把细胞直径设为 8 px | 96 / 103 | 9% | 13% | 24% | 0.82 | 3.39 |
| 再按训练帧调阈值（噪声倍数 40、边缘留白 6、相对下限 0.6） | 96 / 103 | **80%** | **84%** | 99% | 0.82 | 0.74 |

调好后的混淆矩阵（行：真值，列：Vexel，3 表示 3 个及以上）：

```
        0   1   2  3
0      35   2   0  0
1       7  31   2  1
2       0   5  11  0
3       0   0   2  0
```

剩下 19 个错误逐个看过：

| 原因 | 个数 | 方向 |
| :--- | ---: | :--- |
| 珠子贴在液滴轮廓上，被暗环遮住一部分，没数到 | 8 | 少数 |
| 两个珠子挨在一起，数成一个 | 5 | 少数 |
| 液滴里的小杂质被当成珠子 | 4 | 多数 |
| 标注本身可疑（只有一个小点却标了珠子；有两个重叠珠子却标 0） | 2 | – |

## 三、发现

1. **默认设置在这段视频上完全不能用**，而且失败点都在“猜设置”这一步，不在计数本身：
   - 抽帧使液滴几乎不动，时间中值背景把液滴当成了背景，找圆的自动直径范围于是被轮廓碎片带偏（35 帧找出 2234 个“液滴”）。给出直径范围、关闭运动门控后，103 个液滴找到 96 个。
   - 自动阈值以图像噪声为尺度。这段视频经过 JPEG 压缩和缩放，噪声估计偏低，阈值因此太低：轮廓内侧的阴影和小杂质都被数了进去（平均每滴数出 3–5 个）。要把噪声倍数提到 40（默认 6）才合适。
2. **调好设置后**，留出帧上 84% 完全正确，99% 误差不超过 1；λ 少估 10%（0.74 对 0.82）。与 WSCNet 的 92% 在同一个区间。
3. **两套数据剩下的错误是同一类**：挨在一起或重叠的目标数少了，贴着液滴轮廓的目标漏数。这正是经典“找斑点”方法难做、而用液滴裁切图训练的小分类器擅长的情况。WSCNet2 自己也是用训练好的模型做“空/单/多”分类。
4. 小模型解决不了第 1 条：设置猜错时，液滴都找不准，换计数方法也没用。

## 四、三项经典改进的结果（2026-11-14）

每项都在 WSCNet、Droplet-Bead、合成数据（普通、低对比、密集细胞）上同时量化，只保留不让任何一套变差的改动。

| 改进 | 做法 | 结果 |
| :--- | :--- | :--- |
| 1. 自动阈值不只看噪声 | 试了三种：在检测尺度上直接量噪声；只用不受细胞影响的一侧量噪声；以每帧最明显斑点为参照的下限 | **没有采用。** 前两种在 Droplet-Bead 上从 9% 提到 57–67%，但 WSCNet 从 92% 降到 60–76%。原因是两套数据的噪声相关性相同（平滑后噪声是白噪声假设的 4.3 倍和 5.4 倍），区别不在噪声。逐帧下限对没有珠子的帧无效（参照对象本身就是杂质）。在整段录像上看斑点强度分布：WSCNet 和合成数据是清楚的双峰，Droplet-Bead 的杂质和珠子强度连成一片，**只凭对比度分不开，要看形状**（珠子是带亮心的环） |
| 2a. 按面积拆分粘连 | 斑点范围约为同帧典型斑点的 2 倍或 3 倍、且强度不低于该帧最强斑点一半时，按 2 或 3 个计 | **采用，默认开启。** WSCNet 从 92.4% 到 **96.2%**（132 个中错 5 个），λ 1.49 → 1.52（人工 1.57），没有多数；Droplet-Bead（调好阈值）留出帧 84% → **87%**，平均计数 0.74 → 0.82（真值 0.82）；合成数据不变 |
| 2b. 丢弃小杂质 | 范围小于细胞面积一定比例的斑点不计 | **只作可选参数**（`min_size_fraction`，默认 0）。设 0.4 时 WSCNet 降到 83%（暗淡细胞的范围也小），Droplet-Bead 几乎不变（它的杂质主要是轮廓阴影，不是小点） |
| 3. 识别不动的液滴 | 探针发现默认识别不可信（很多小圆，或没有流动）时，不用运动门控，按直径分段扫描，选“少数大而一致的圆”覆盖面积最大的一段；规划器据此设定直径范围、关闭运动门控、提高轮廓完整度要求。`seg.motion_threshold=0` 现在表示真正不用运动门控 | **采用。** Droplet-Bead 上自动规划不手填任何设置即找到 89/103 个液滴（原来 20/103），直径约 60 像素；纯噪声、正常流动的录像（WSCNet、.mov、合成）不触发 |

改进后 Droplet-Bead 的完整结果（`tests/benchmarks/bead_counting_eval.py`）：

| 设置 | 找到的液滴 / 标注 | 完全正确 | 留出帧上完全正确 | 平均真值 | 平均计数 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 自动规划（不手填设置） | 89 / 103 | 2% | 0% | 0.79 | 5.55 |
| 调好计数阈值（同前） | 94 / 103 | 74% | 87% | 0.81 | 0.82 |

**结论**：拆分粘连和识别不动液滴是确定的改进。压缩视频上“哪些斑点是细胞或珠子”这一步，经典方法在不调参时仍做不到；调参后能达到 87%。这一步正是小模型要解决的问题，下面的决定条件不变。

## 五、建议（改进前写的；决定条件仍然适用）

**现在不训练小模型，先做三项经典改进；内测结束后按下面的条件决定。**

**先做（几天的工作量，每项都能在两套数据和合成基准上量化）：**

1. **自动阈值不再只看噪声。** 当前要求斑点对比度超过噪声乘以一个倍数；改为同时以每帧最明显斑点的对比度为参照（“相对下限”这条规则已有）。Droplet-Bead 上作用最大的是这两项：噪声倍数从 6 提到 40，相对下限从 0.3 提到 0.6。目标是让压缩过的视频不用手调。
2. **按大小区分目标与杂质，按面积拆分粘连。** 斑点明显小于设定的细胞直径就丢弃（杂质）；斑点面积约为单个细胞的 2 倍或 3 倍时算 2 个或 3 个（粘连）。粘连是两套数据共同的错误：WSCNet 的全部 10 个，Droplet-Bead 的 5 个。贴轮廓漏数（Droplet-Bead 的 8 个）经典方法较难改进，留作决定小模型时的重点观察项。
3. **探针与规划器识别“不动的液滴”。** 发现液滴帧间几乎不动（抽帧、停流、静态阵列）时，关闭运动门控，用单帧估计直径范围，并在方案理由里写明。这一条同时惠及将来的静态阵列芯片。

**内测结束后的决定条件：** 用测试者的真实录像，加上他们在复核窗口里的修正（修正就是标注），在没参与调参的数据上量计数准确率。

- 经典改进后，完全正确率 ≥ 95% 且 λ 偏差 ≤ 5%：不做小模型。
- 达不到、且测试者把计数列为主要问题：训练小模型。任务为 `count.inclusions`，输入是液滴裁切图，输出 0/1/2/3+，按[插件接口](plugin_interface.md)接入，可以原样替换配方里的 `droplet.inclusions`。

**训练小模型需要的数据：**

| 来源 | 规模 | 状态 |
| :--- | :--- | :--- |
| Gardner 等（PC3 细胞） | 数千液滴 | 需你在 Roboflow 登录下载（cropped_drops2 与 pc3dropletdetection2 两个项目），并核实许可证 |
| 测试者的修正 | 视内测规模 | 复核窗口已保存修正记录，需征得同意后用于训练 |
| 合成数据 | 不限 | 已有生成器，可专门生成粘连和贴边的情况 |
| Droplet-Bead | 约 100 个液滴实例 | 太少，只适合做测试集 |

注意：若用了非商用许可的数据训练，模型卡会自动标成“不可商用”（路线图第十二节的要求），将来商用时需要重训。
