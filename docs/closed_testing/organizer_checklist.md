# 内测组织清单（给组织者）

目标：用 2 周、3–5 位测试者，拿到**真实客户数据**和**失败案例**，同时完成第四阶段的 15 分钟可用性验收。依据见 [微流控开发进度评估](../progress_microfluidics.md)。

## 发放前

- [ ] 确认 CI 在 Windows、Linux 上全绿（`.github/workflows/ci.yml`）；有条件时再在一台真实的 Windows 电脑上按 [内测说明](README.md) 从零安装一次，看界面显示。
- [ ] 构建发放文件：`scripts/build_dist.sh`，得到 `dist/` 下的 wheel、依赖版本约束文件 `vexel-0.6.0b1-constraints.txt` 和 `SHA256SUMS.txt`（CI 每次也会构建同样的文件，并在 macOS、Windows、Linux 上按测试者的方式安装和试运行）。三个文件一起发放。
- [ ] 分发：同一套文件放两处——GitHub Releases（海外测试者）和一个国内下载点（对象存储或网盘，大陆测试者）。
- [ ] 在大陆网络下按内测说明 1B 实际装一次（CI 测不到国内网络）。
- [ ] 决定分发方式：发 .whl 文件（不需要 GitHub 账号），或把测试者加为私有仓库的协作者（能看到源码）。
- [ ] 决定反馈渠道（微信群 / 邮箱 / GitHub issues）并写进内测说明的“联系”一栏。
- [ ] 数据约定：测试者提供的录像只用于内部开发与测试、不公开、可要求删除；有合作协议时以协议为准。确认后写进说明。
- [ ] 打 tag：`git tag v0.6.0b1`（发放的版本可追溯）。

## 招募

- [ ] 3–5 位做液滴实验的研究生或技术员，尽量覆盖：有细胞包裹的、有荧光（ddPCR）的、用 Windows 的、不熟悉图像分析软件的。
- [ ] 每人请准备至少 3 段录像，并尽量有一个已知答案（人工数过、显微镜量过、已知包裹率或阳性率）。

## 第 1 天

- [ ] 发：内测说明、反馈表、已知问题、安装文件或仓库邀请。
- [ ] 可用性测试：请测试者第一次打开时**录屏并计时**（内测说明第 2 步），或约 30 分钟视频会议按 [可用性测试方案](../usability_test.md) 观察，不提示。

## 期间

- [ ] 每 2–3 天看一次反馈；崩溃和“结果不对”优先。
- [ ] 收到的诊断包：`unzip -l` 看清内容；按 `environment.json` 复现环境，按 `recipe.json` 和 `summary.json` 复现运行。
- [ ] 收到的录像：放进 `microfluidics dataset/`（不入仓库），在 `tests/realdata/` 记录来源、许可与真值；能定真值的加入真实数据回归。
- [ ] 每个确认的问题建一条记录：现象、影响的测试者数、严重程度、是否已修。

## 结束时

- [ ] 收回问卷（反馈表 C 部分）。
- [ ] 汇总：
  - 15 分钟可用性：多少人在 15 分钟内完成，填进 [usability_test.md](../usability_test.md)；
  - 每段真实数据的结果与参照的偏差；
  - 自动规划的 ready / check / needs_user 比例；
  - 问题清单按影响排序；
  - 需求清单按提及人数排序。
- [ ] 据此更新路线图第十节的验收状态，确定第六阶段（批处理）与第七阶段（安装包）的优先级。
- [ ] 若有人使用了云端模型：用 `tests/benchmarks/agent_acceptance.py --model <来源>` 补测联网规划通过率。

# SEM 模块内测（M7，0.7.0b1 起；当前 0.7.0b2）

目标：第一位 SEM 用户（半导体制造）用 2–3 周，拿到**真实 CD-SEM 图像与 CD-SEM 的参考值**，完成半导体计量的真实数据验收，同时收集识别分类器（M5 后半）的训练与评估图像。给测试者的文件在 [sem/](sem/README.md)。

## 发放前

- [ ] CI 全绿；`uv run python tests/benchmarks/sem_real_eval.py --data <SEM 样图文件夹>` 与各 SEM 合成验收脚本通过。
- [ ] `scripts/build_dist.sh` 构建当前版本；在一台干净的 Windows 电脑上按 [SEM 内测说明](sem/README.md) 从零安装一次（带 `[sem]`），确认 `vexel gui --module sem --preview` 能打开、信息栏文字能读出；在大陆网络下按镜像设置装一次。
- [ ] 与对方确认 [数据需求](sem/data_request.md) 末尾的保密约定（产品名与批号、能否保留脱敏小块做回归测试、结束后如何处理、报告给谁看、谁解答参考值问题）。有保密协议时以协议为准。
- [ ] 约定数据的传递方式（加密盘或对方指定的方式），**不经过公共网盘或聊天软件传图像**。
- [ ] 决定反馈渠道，写进 SEM 内测说明的“联系”一栏。
- [ ] 打 tag：`git tag v0.7.0b2`（每次发放新版本都打）。

## 第 1 天

- [ ] 发：SEM 内测说明、数据需求、反馈表、已知问题、安装文件。
- [ ] 约 30 分钟视频会议：请对方第一次打开时不看手册，录屏并计时（内测说明第 2 节）。

## 期间

- [ ] 收到的图像放在仓库之外（例如 `~/VexelData/sem/<客户代号>/`），**不进入仓库，不上传任何云服务或大模型**；按清单记录仪器、参考值与算法设置。
- [ ] 每批图像：用 `vexel sem analyze` 按对方 CD-SEM 的边缘定义重跑，把差值、重复性写进 `docs/sem_module_plan.md` 的验收表；发现问题按“现象 / 影响 / 严重程度 / 是否已修”记录。
- [ ] 诊断包：`unzip -l` 看清内容（不含图像与信息栏文字），按 `calibration.json` 与 `measurements.json` 复现。
- [ ] 第一次收到 Hitachi CG 系列文件时，先核对 `.txt` 旁车文件的字段与我们的读取是否一致（像素尺寸、信息栏行数）。

## 结束时

- [ ] 汇总：标定是否全部正确；线宽在相同边缘定义下与 CD-SEM 的差（平均与最大）；重复性 3σ 与 CD-SEM 的比；自动规划的 ready / check / needs_user 比例；问题与需求清单。
- [ ] 据此决定 SEM 模块能否从“预览”改为“可用”（`src/vexel/modules/__init__.py` 中的 `status`），以及 M5 后半（分类器）与界面 P1 的优先级。
- [ ] 按约定处理数据（删除或保留到约定日期），并书面告知对方。
